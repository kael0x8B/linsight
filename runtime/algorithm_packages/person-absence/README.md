# 指定人员离岗 2.0.0

选择已授权人员库和 **一位** 指定登记人员，框选岗位区域。其他人在区域内不能代替该人员。多个岗位/指定人员分别配置任务。1.0.0 为历史人数版，不满足指定身份要求，保持旧配置固定版本。

## 判断与告警

- 人员检测 + 人脸检测/特征模型，复用已有模型角色与授权参考；不新增独立离岗模型。
- 本人相似度默认至少 0.6，最近 5 帧至少 3 帧一致；明确低于 0.3 且多帧一致才作为其他人。中间值、低清、遮挡、多人脸或参考过期均为“身份待确认”。
- 本人已核验且人体框持续一对一关联时，可保留身份 10 秒。交叉、人体消失、观测间隔超过 3 秒或保留超时必须重新核验。不会把身份永久挂到座位或衣服上。
- 无人或确认只有其他人时才生成离岗候选。默认 3/5 帧后持续 60 秒告警，本人确认返回后按恢复时间关闭。短暂离开不会立刻告警。
- 身份待确认通过 `observationValid=false` 暂停确认和恢复；既有告警不因看不清而关闭。不包含活体校验。

## 配置

“识别参数”选择人员库、指定人员并框选岗位范围；“告警条件”调整持续时间、N/M、恢复和冷却。岗位范围以识别参数中的矩形为准，默认告警区域保留全画面，以便接收岗位状态。规则中心可配置值班时段。

输出框代表岗位状态区域，不是虚构的人体框。正常/离岗/待确认显示不同文本和颜色，不显示伪造的 100% 识别置信度。

需要支持 `observation-validity-v1` 的 Runtime。旧网关会拒绝执行该包；须升级后再部署。后台 API、人员库权限、参考有效期、模型版本和证据上传沿用既有机制。

## 验证边界

必须用指定真人完成在岗、本人离开、其他人替岗、本人返回、背对镜头及遮挡的连续视频验证。远景办公摄像头未检测到可用正面人脸时应显示待确认，不能以人数版测试或合成人像测试宣称指定人员验收完成。2026-09-10 现场情况及测试证据见项目文档 `docs/PERSON_ABSENCE_20260910.md`。
