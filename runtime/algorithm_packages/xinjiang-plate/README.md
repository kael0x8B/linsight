# 厂区车辆识别（新疆优化）1.0.0

独立可安装算法包，编码 `xinjiang-plate-package`。旧「厂区车辆识别」及「车牌识别」的编排、模型绑定、配置和解码结果不自动更改。本包不含模型权重，不修改共享模型实例。

## 安装与使用

1. 在模型中心准备盒子兼容、已验证的车牌四角定位与专用 OCR 版本。支持 YOLO_PLATE / YOLO26_PLATE_POSE 定位、CHINESE_PLATE_CTC / PLATE_OCR_ROUTED OCR；不支持无字符候选信息的 LPRNet。
2. 通过算法中心上传并发布 `xinjiang-plate-package-1.0.0.zip`。
3. 在目标网关「添加识别算法」中选择「厂区车辆识别（新疆优化）」，选择摄像头，在高级设置核对具体模型版本及参数。首次比较使用独立测试任务，不绑定正式对外事件接口。
4. 原任务仍绑定原算法。不要删除、改写或自动迁移原任务。多任务共享摄像头解码，但推理和工作进程仍增加资源消耗，应先验证盒子容量。

## 兼容前提

本包使用 SDK 1.0 的可选 `plate-ocr-evidence-v1` 能力；网关必须报告该能力。只有解码后文字的旧 Runtime 无法提供真正的首字候选比较，安装/启动前须明确拒绝，不静默退化成字符串替换。本包**不能直接用于缺少该能力的现有盒子**。

首次补充这一通用输入能力需要发布兼容 Runtime；后续新疆规则改动通过独立 ZIP 版本发布，无须因业务规则变更而更新 Runtime。仅发布新包不会升级正在运行的任务。本分支没有升级现场盒子，运行版本回退须在隔离目标硬件上验证后再安排。

输入沿用主程序的定位、原图透视裁剪、上下文重试和物理跟踪；普通包仍沿用原输入流程。输出的 `ocrEvidenceJson` 保存未加权的字符发射分数，CTC blank/重复字符已经正确折叠；这些分数不是校准后的真实正确率。

## 判定行为

- 先按同一物理 trackId 确认号码主体。无效、漏检帧占据窗口；重复时间戳不加票；过期、倒序观测不累积。不同车辆不能因号码主体相同而合票。
- 普通 7/8 位及既有支持的挂车号牌保持号码主体不变；字母、数字低分时继续待确认。
- 清晰外省结果按原省份确认；窗口内的清晰外省证据否决改成“新”。清晰省份互相冲突时待确认。
- 模型确实支持“新”、与其他省份差距小，且多帧主体一致时，应用一次地区排序加分，输出 `provinceSource=REGION_ASSISTED`。
- 首字完全缺失时补“新”默认关闭。开启后标记 `REGION_INFERRED`；其事件输出还需单独开启 `allowInferredEvents`，默认只展示推断结果。
- 原 `plateText`、`ocrConfidence`、`ocrMinCharConfidence` 不被改写。包不生成夸大的 `plateConfidence`；展示分数为 null，保留省份判定来源。
- 支持省份未知的上下文双裁剪，只接受两个裁剪的号码主体清晰一致，且不存在清晰省份冲突；两次裁剪不算两帧。

默认 3/5 帧、10 秒窗口；主体最低分 0.75、省份直接确认分 0.75、新字候选最低分 0.20、最大分差 0.10、排序加分 0.12。**这些是保守工程初值，尚无现场准确率结论，必须用新疆厂区标注录像校准。**

## 比较与恢复

先保留旧任务、旧模型精确版本、规则和参数快照，用相同的标注录像比较：整牌正确、整牌认错、未确认；另统计外省误改“新”、原来正确而新算法错误、确认延迟和重复事件。不能把确认数量增加等同准确率提升。发布包和通过单测都不代表现场效果验收。

算法效果不好：停止新任务，继续或恢复原任务；不需要替换模型或删除新包。升级算法包时，保留旧包 SHA256/版本及对应参数快照，停止任务后选回旧版本。应用 Runtime 升级故障属于另一条回退路径；本包不提供、也不宣称已经验证现场应用版本回退。已产生的历史事件保留。
