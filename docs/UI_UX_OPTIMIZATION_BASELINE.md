# LInsight 控制台 UI/UX 优化基线

> 日期：2026-09-02  
> 范围：`frontend/apps/web-antd`，不改变业务状态机、接口语义、权限或数据所有权。

## 1. 现状主要问题

1. 运行总览原先以 Story 交付进度和现场验收引导为中心，不符合日常运行驾驶舱的任务目标；告警、离线、异常任务未形成首屏优先级。
2. 全局 Ant Design Token 基本沿用模板默认值，Card、Table、Drawer、输入控件、状态颜色和阴影缺少 LInsight 自身的视觉约束。
3. 登录页仍显示上游“中后台模板”宣传文案；用户菜单保留上游文档、GitHub、帮助入口，削弱商业产品完整性。
4. 页面标题区不统一：部分页面没有标题与说明，部分把主操作放在表格内部，部分依赖 Alert 解释页面。
5. 算法中心仍以数据库表为主，缺少按场景发现能力的 Marketplace 体验。
6. 摄像头只有列表视图，视频源状态虽可读但视觉优先级不足；缺少面向巡检的卡片视图。
7. 事件列表没有证据缩略图，事件等级、处置状态和事件事实混在等权文本列中。
8. 边缘节点资源使用以一行拼接文本展示，CPU、内存和 GPU 压力不易比较；操作列包含过多并列文字操作。
9. AI 任务使用英文状态值，实际/期望状态漂移不够醒目；复杂七步配置放在大 Modal 中。
10. 多个页面分别维护颜色映射、状态标签和页面间距，存在重复样式与语义漂移。
11. Dashboard、算法、任务和事件页面手工组合 Ant Table；已有页面继续保留既有数据流，本轮优先收敛视觉与交互，新 CRUD 仍应优先使用 Vben Grid/Form/Drawer。
12. API 当前没有摄像头卡片所需的任务数量、运行算法、最近事件聚合投影，也没有 Dashboard 专用趋势聚合。本轮不通过 N+1 请求或伪造数据补齐，Dashboard 对事件样本口径做显式标注。

## 2. 统一视觉规范

### 2.1 色彩语义

| 语义 | 色彩 | 用途 |
| --- | --- | --- |
| 正常 | `#16a34a` | 在线、运行、Ready、成功 |
| 严重 | `#dc2626` | 错误、离线、严重告警 |
| 警告 | `#d97706` | 异常、同步中、重要事件 |
| 信息 | `#2563eb` | 配置、链接、选中态 |
| 中性 | `#64748b` | 停止、未启用、未知 |

状态必须使用“状态点 + 文本”或“图标 + 文本”，不只依赖颜色。事件严重等级与检测目标类别颜色分离。

### 2.2 尺寸与密度

- 页面内容最大宽度：常规控制台 `1680px`，视频工作区 `1920px`。
- 页面间距：标准 `16px`，1440px 以下收敛为 `12px`。
- 圆角：小控件 `6px`，输入/按钮 `7–8px`，主容器 `12px`；不使用大面积胶囊卡片。
- 控件高度：默认 `34px`；正文 `14px`，说明 `12–13px`，KPI `29px`。
- 阴影仅用于可交互卡片、浮层和 Hover；静态分组优先使用背景层级与留白。

### 2.3 页面结构

标准业务页顺序：产品级标题区（标题、说明、一个主操作）→ 风险/状态概览 → 常用筛选 → 主内容 → 分页。复杂详情与配置使用 Drawer；简单新增/确认可使用 Modal。危险操作显示对象、影响和可恢复性。

### 2.4 响应式与可访问性

- 重点验证 `1366×768`、`1920×1080`、`2560×1440`。
- 核心操作保持键盘焦点可见，图标按钮提供可访问名称或 Tooltip。
- 轻量运行脉冲尊重 `prefers-reduced-motion`。
- 首次加载使用 Skeleton；刷新保留旧数据并显示局部 Loading；空态说明原因和下一步。

## 3. 本轮公共能力

- `linsight.css`：全局 Token、Ant/Vxe 表格密度、Card/Drawer/Modal、内容宽度和暗色兼容。
- `AiPageHeader`：统一标题、辅助说明、业务标识和主操作。
- `AiStatusIndicator`：统一在线、运行、异常、停止等状态语义。
- `AiMetricCard`：Dashboard 高密度指标与风险优先级。
- `AiResourceGauge`：CPU、Memory、GPU 等资源指标。

## 4. 页面改造映射

| 页面 | 已落实的优化 |
| --- | --- |
| 登录/Layout | 产品文案、本地品牌标识、收敛模板入口、导航与页签密度 |
| Dashboard | 告警优先 KPI、今日趋势、等级分布、在线率、节点资源、最近告警 |
| 摄像头 | 列表/卡片切换、视频缩略工作区、显式状态、快捷预览、更多菜单 |
| 实时视频 | 保留深色专注工作区、播放器中心、摄像头列表和 AI Overlay 控制 |
| 算法 | 卡片 Marketplace、类别/状态快速筛选、场景/实现类型、Pipeline 工作区 |
| 模型 | 统一页面头、格式/来源/发布/部署状态、版本与部署 Drawer |
| AI 任务 | 中文运行状态、漂移提示、运行轻动画、七步配置迁移到 Drawer |
| 事件 | 证据缩略图、等级侧色条、状态点、证据中心详情和处置二次确认 |
| 节点 | CPU/内存/GPU 资源条、运行状态、主操作 + 更多菜单 |
| 规则/模型测试/Webhook/日志/参数 | 统一页面标题、内容宽度、操作层级和全局组件样式 |

## 5. 后续数据契约建议

若需要让 UI 展示全部目标字段，应新增只读聚合接口，而不是前端 N+1：

- Camera Card Projection：`taskCount`、`runningAlgorithms[]`、`latestEvent`、`snapshotUrl`。
- Dashboard Summary/Trend：准确的今日事件、24 小时趋势、事件类型分布、异常任务与资源聚合。
- Model Projection：关联算法数量、设备支持集合、输入尺寸与 Labels 摘要。
- Node Projection：运行任务数、摄像头数、GPU 显存、磁盘、温度与短时趋势。

这些建议不改变领域所有权：只读组合由 Query Service 聚合，各领域仍通过 owner Service 提供投影。
