# ADR-0002：通过 SSH 完成边缘节点初始接管部署

- 状态：Accepted；在线重部署与生命周期扩展见 ADR-0006
- 日期：2026-09-03
- 范围：Node 领域、AI Runtime、Edge Agent

## 背景

Edge Agent 已具备注册、心跳和在线升级通道，但首次安装仍要求运维人员登录 Linux 网关手工准备 Python、FFmpeg、环境变量和 systemd。首次安装时 Agent 尚未在线，既有节点命令通道无法使用。

## 决策

管理控制面在 Node 领域提供一次性的 SSH 初始接管流程：

1. 管理员输入目标主机、SSH 用户和密码并执行预检。
2. 控制面返回系统、架构、Python、磁盘、内存、FFmpeg、NPU 设备与 SSH 主机指纹。
3. 管理员确认指纹后创建异步部署任务。
4. 控制面打包当前 `runtime` 源码，上传到固定临时目录，安装依赖和 systemd 服务，并自动生成一次性注册令牌。
5. Agent 注册成功后立即从节点环境文件中删除 bootstrap token；长期节点凭据仅由 Agent 写入权限为 `0600` 的本地文件。
6. 初始接管完成后，版本升级继续使用既有的签名 Agent 命令通道，不持续开放 SSH 控制能力。

控制面只持久化目标主机、预检摘要、阶段、进度和脱敏错误；SSH 密码、bootstrap token、Runtime API key 与主机公钥正文均不入库。API 访问日志对密码和主机密钥字段进行脱敏。

## 结果与边界

- 复用仓库已使用的 JSch，不引入新的远程执行框架。
- 首次预检采用 TOFU（Trust On First Use）；正式部署必须固定并校验预检获得的主机公钥。
- Linux 节点必须具备 sudo，并满足 Python 3.12/3.13、至少 1 GiB 内存与 2 GiB 可用磁盘。
- 当前 ARM64 基线使用 ONNX Runtime CPU。发现 `/dev/rknpu` 只作为硬件信息展示，在 RKNN 执行适配器完成前不宣称 NPU 推理可用。
- 部署任务不可在服务重启后恢复，因为凭据不持久化；失败记录保留审计信息，可由管理员重新发起。
