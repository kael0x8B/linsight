# LInsight 开发计划与页面级规格

> 依据《通用 AI 视频智能分析平台需求规格说明书 V1.2》制定。计划以核心业务闭环和技术风险为权重，不以页面数量平均分配资源。

## 1. 目标与交付原则

V1.0 的最短价值链为：摄像头可用 → 视频可看 → 模型可部署 → 任务可运行 → 规则可确认 → 事件有证据 → 人员可处置 → 断网仍可分析。所有开发都围绕这条链路排序。

- 管理面只新增一个 AI 视频业务域，复用现有登录、RBAC、租户、日志、文件和字典能力。
- Java 控制面不承载 RTSP 长连接、FFmpeg 解码和模型推理；AI Runtime / Edge Agent 独立运行。
- 同一摄像头只拉流和解码一次；Detector、Tracker 与帧结果在算法间共享。
- Algorithm 与 ModelVersion 解耦；规则型能力不训练伪“独立模型”。
- 所有行为事件必须经过连续帧或持续时间确认，禁止单帧直接告警。
- 每个页面必须完整覆盖 loading、empty、error、no-permission、offline、partial-data 状态。

## 2. 能力权重：从核心到边缘

| 层级 | 能力域 | 权重 | 为什么排在这里 | 完成标志 |
| --- | --- | ---: | --- | --- |
| L0 | 平台基座与安全 | 8% | 所有业务的入口和治理底线 | 基座可启动、RBAC/审计/文件可复用 |
| L1 | 摄像头与视频链路 | 18% | 没有稳定视频就没有 AI | RTSP 检测、预览、断流重连、共享解码 |
| L2 | 模型、算法与任务编排 | 22% | 决定能力是否可配置、可替换、可运行 | 模型版本、Pipeline、任务全生命周期 |
| L3 | 规则、事件与证据闭环 | 24% | 是平台真正交付给业务的结果 | 去重、截图录像、处置、误报反馈、通知 |
| L4 | 11 类算法效果 | 18% | 业务覆盖广，但依赖 L1-L3 的通用底座 | 逐算法指标与场景验收通过 |
| L5 | 边缘自治与工程化 | 10% | 决定规模化、弱网和生产可用性 | 节点管理、离线补传、升级回滚、压测 |
| 合计 |  | **100%** |  |  |

资源建议：后端/前端/Runtime/算法/测试以跨职能小组推进；L1-L3 期间 Runtime 和控制面必须同步交付契约，避免先做完页面再补真实链路。

## 3. 里程碑与依赖

### M0 基座就绪（已完成，权重 8%）

- 固定后端、前端 tag/commit，完成品牌替换和无关内容清理。
- MySQL、Redis、MinIO、Java API、Vue 管理端可本地启动。
- 保留系统/基础设施能力，建立环境变量、Compose、启动与检查脚本。
- DoD：新开发者按 README 在 30 分钟内启动；管理员可登录；健康检查通过。

### M1 视频接入闭环（权重 18%）

- Camera/CameraGroup 表、加密凭据、RTSP/ONVIF 检测、周期心跳。
- Runtime 实现 FFmpeg 拉流、重连、帧采样和 WebRTC/HLS/FLV 中至少一种浏览器预览适配。
- 单画面预览、Overlay 协议、手工截图；再扩展 4/9/16 视频墙。
- DoD：新增一个 RTSP 摄像头，完成检测、预览、断流/恢复状态变化；一源多订阅不重复拉流。

### M2 AI 资产与任务闭环（权重 22%）

- 模型资产登记、SHA256、许可证门禁、版本发布/回滚、节点下载状态。
- 将 EasyAIoT README 当前列出的 12 个内置模型全部登记为预置资产；逐个完成格式识别、单图推理、节点部署和结果标准化。
- Algorithm capability graph 与 Pipeline 定义；Detector/Tracker/Classifier/Rule 插件接口。
- Task 创建向导、参数校验、幂等启停、状态和指标上报。
- DoD：一个 Person Detector 模型可上传、单图测试、下发节点，并由任务启动真实推理。

### M3 规则与事件闭环（权重 24%）

- ROI 编辑器、归一化坐标、时间段、N/M 帧、持续时间、数量、冷却、组合逻辑。
- DETECTED → PENDING → CONFIRMED → ALARM → COOLDOWN → RECOVERED/CLOSED 状态机。
- 截图、前 10 秒 + 后 20 秒录像、事件去重、处置记录、误报困难样本。
- WebSocket 和 Webhook；通知失败重试与签名。
- DoD：区域入侵从画框到实时告警、证据、处置、误报反馈全链路可演示。

### M4 11 类算法分批验收（权重 18%）

1. 基础复用先行：Person Detection、Tracking、ROI、Vehicle Detection。
2. 规则型：人员闯入、区域入侵、人员离岗。
3. 目标/属性型：安全帽、反光衣、车辆。
4. OCR：车牌检测与多帧 OCR 投票。
5. 高风险事件：火焰、跌倒。
6. 高误报行为：吸烟、打电话，最后集中优化困难样本。

每个算法必须固定模型来源、commit/tag、SHA256、许可证、推理后端、阈值基线和测试集版本。EasyAIoT 对应模型优先复用；车辆检测自研；闯入/入侵/离岗由 Person Detector + Tracker + Rule 实现。

### M5 边缘自治与生产硬化（权重 10%）

- Agent 注册/认证、资源上报、模型断点续传/校验/回滚、任务配置版本化。
- 中心断网继续分析，事件与媒体本地落盘，恢复后按幂等键补传。
- 节点日志、远程诊断、灰度升级；V1.0 手动调度，自动调度列为 P2。
- DoD：断网 30 分钟期间事件不丢；恢复后状态、事件、媒体一致；版本回滚可验证。

## 4. 技术落地结构

### 4.1 后端

新增单一业务模块 `linsight-module-ai-video`，沿用基座的 `api/server` 双子模块与 Controller → Service → DAL 分层，并在各层内部按领域分包，而不是拆成多个微服务：

```text
camera/       摄像头、分组、连通检测、流状态
model/        模型资产、版本、许可证、节点部署
algorithm/    算法定义、能力图、Pipeline
task/         任务配置、命令、状态、指标
rule/         ROI、时间、帧、持续、冷却、组合规则
event/        状态机、证据、处置、误报、通知
node/         Agent、心跳、资源、日志、升级
integration/  WebSocket、Webhook、开放 API
```

控制面 REST 统一使用 `/admin-api/ai-video/**`；节点面使用独立认证的 `/node-api/ai-video/**`。命令必须包含 `commandId`、`configVersion` 和幂等键；状态上报不得依赖页面轮询。

Module、Package、领域责任、跨域依赖和编码门禁统一遵循 [ARCHITECTURE_AND_CODING_GUIDELINES.md](ARCHITECTURE_AND_CODING_GUIDELINES.md)。任何拆 Module、拆服务或改变数据所有权的方案必须先提交 ADR。

核心表：`ai_camera_group`、`ai_camera`、`ai_model`、`ai_model_version`、`ai_algorithm`、`ai_task`、`ai_rule`、`ai_event`、`ai_event_media`、`ai_event_action`、`ai_edge_node`、`ai_node_command`、`ai_webhook`。大字段配置先用有版本的 JSON Schema，稳定后再拆列。

### 4.2 Runtime / Edge Agent

- V1.0：Python + FastAPI/gRPC + FFmpeg/OpenCV + ONNX Runtime。
- 分层：StreamHub → FrameSampler → CapabilityGraph → Tracker → RuleEngine → EvidenceBuffer → EventUploader。
- `StreamHub(cameraId)` 独占拉流/解码，多任务按分析 FPS 订阅帧；`ModelPool(modelVersionId)` 复用模型实例。
- 结果坐标内部统一为 `[0,1]` 归一化；对外结果携带原帧宽高、frameId、timestamp、trackId。
- 本地 SQLite/轻量队列记录离线事件索引，媒体文件按配额和 TTL 管理。

### 4.3 前端

- 业务代码放在 `frontend/apps/web-antd/src/views/ai-video` 与 `src/api/ai-video`。
- 菜单和按钮权限编码统一为 `ai-video:{domain}:{action}`。
- 列表采用统一搜索栏 + VxeGrid；复杂创建流程用整页向导，轻量编辑使用右侧 Drawer。
- 视频 Overlay 使用 Canvas/WebGL 独立层，不把框画进 `<video>`；按容器缩放和 letterbox 偏移做坐标映射。

### 4.4 统一结果与实时协议

检测结果至少包含 `frameId/timestamp/cameraId/objects[]`，目标包含 `trackId/class/confidence/bbox/attributes`。事件 WebSocket 消息使用 envelope：`type`、`version`、`messageId`、`occurredAt`、`data`。所有协议从 V1 开始版本化。

## 6. 逐页需求、实现与 UI 细节

### P01 登录

- 需求：账号密码登录、状态保持、退出；默认关闭验证码，生产可配置开启；租户域名或租户选择可用。
- 实现：复用现有 Auth API、Token 刷新和权限路由；生产环境登录限流、失败锁定和审计必须开启。
- UI：品牌标题为 LInsight；仅保留登录表单、记住我和必要错误提示，不显示上游推广/帮助外链。错误区分账号错误、锁定、网络异常；提交时按钮 loading 且禁止重复提交。
- 验收：登录后进入运行总览；刷新保持状态；无权限菜单不出现；退出后 Token 失效。

### P02 运行总览

- 需求：显示摄像头在线率、运行任务、今日事件、在线节点；趋势、严重事件、异常任务和节点资源概览。
- 实现：聚合 API `/dashboard/summary`、`/event/trend`、`/task/abnormal`；统计使用按分钟预聚合，禁止对事件大表实时全表扫描。WebSocket 增量更新事件和状态。
- UI：第一行 4 张 KPI 卡；第二行“24 小时事件趋势 + 事件等级分布”；第三行“重点事件 + 异常任务/节点”。KPI 必须同时展示数值、分母或同比口径、更新时间。卡片可点击钻取对应筛选页。
- 状态：数据陈旧超过 60 秒显示“数据延迟”；无节点时展示接入引导，不伪造 0% 健康度。
- 2026-09-09 首页布局优化：顶部统一为摄像头在线率、运行任务、今日事件和在线节点 4 张卡片；待处置事件、离线摄像头、异常任务和离线/未知节点合并为紧凑关注栏。下方采用对齐的两列布局，上排为今日趋势和等级占比，下排为重点告警和运行健康，模型/算法入口收至健康卡片底部。重点告警优先展示未完成处置的事件，并支持直达详情；窄屏自动堆叠。当前事件及任务状态沿用最近 100 条记录的样本口径，明确标注，聚合 API 和 WebSocket 总览增量更新尚未接入。各数据源独立加载，失败保留已有内容，无权限不发起查询；无节点、缺失资源指标均不显示伪造的 0% 使用率。

### P03 摄像头管理

- 需求：新增/编辑/删除、搜索、分组、在线状态、主/子码流、批量检测和导入导出。
- 实现：凭据加密存储，列表永不返回明文密码；删除前检查任务引用；连通检测创建异步 job 并回传分阶段结果（DNS/TCP/鉴权/取流/关键帧）。
- UI：左侧 240px 分组树，右侧筛选栏 + 表格；列含名称/编号/分组/协议/在线状态/最后在线/任务数/节点/操作。状态使用圆点 + 文本，不能只靠颜色。URL 默认脱敏，显式授权后短时查看。
- 交互：批量操作只在选中后出现；高风险删除二次确认并展示受影响任务数；“预览”是首要行操作。
- 2026-10-12 按用户要求移除摄像头列表的“识别能力”列及卡片的能力数量，避免能力标签撑高行。识别任务与实时预览中的能力选择保持原有用途。摄像头编辑改为响应式双列表单，码流路径独占一行；编码要求移至字段帮助，凭据留空保留原值的说明放在表单底部。2026-09-09 已移除列表、卡片的算法设置与批量配置入口及无用途的勾选列，预览为首要操作，编辑和删除收进“更多”；算法配置与启停统一在边缘盒子中操作。

- 历史交付（2026-09-07；入口已于 2026-09-09 移除）：摄像头列表、卡片提供“算法设置”，抽屉内直接添加、启动、停止和移除识别任务；列表/卡片勾选后可跨页批量配置，单批最多 100 台。配置归属仍为 Task，不新增摄像头算法关系表。复用已有任务配置或进入带摄像头选择的新建向导；已有同类算法保留原设置，逐台反馈结果。详见 [摄像头算法管理](CAMERA_ALGORITHM_MANAGEMENT.md)。

### P04 摄像头分组

- 需求：树形新建、改名、移动、删除、排序；显示组内总数/在线数。
- 实现：邻接表 + `path`/层级冗余；移动操作做循环检测和租户隔离；删除非空组必须先迁移摄像头。
- UI：树节点展示 `名称  在线/总数`；拖拽后先显示目标位置确认；搜索保留祖先链；空分组可删除，非空分组提供“迁移到”选择器。

### P05 摄像头详情

- 需求：基本信息、码流、实时预览、任务引用、在线历史、检测记录。
- 实现：Tab 分 API 加载；“测试连接”不保存配置；编辑凭据时空值代表不修改。状态历史按事件存储并支持时间窗口聚合。
- UI：页头显示名称、编号、在线状态、最近心跳和快捷预览；Tab 为概览/码流与认证/关联任务/状态历史/操作日志。敏感字段脱敏；详情页右侧固定“检测连接”“编辑”。

### P06 实时预览

- 需求：识别同源码流低延迟播放、Overlay 开关、截图、静音/全屏、查看最近事件。
- 实现：页面创建 recvonly WebRTC Offer，经 Edge Agent 反向通道与 Runtime 协商；媒体通过 ICE/DTLS-SRTP 直达边缘节点，不静默降级。Overlay 消息按 frame timestamp 与播放时间对齐；截图可选原图或带 Overlay 图。
- UI：视频区域使用深色背景；左侧可搜索摄像头，中心保持画面比例，右侧为图层控制和最近事件。Overlay 图例固定 class 颜色，框标签含类别/置信度/trackId；ROI 为半透明填充 + 虚线边界。
- 状态：加载超过 8 秒显示阶段；断流显示最后一帧 + 重连倒计时；无权限不暴露 RTSP 地址。

### P23 Webhook 集成

- 需求：端点、事件类型、等级过滤、签名密钥、启停、测试、投递记录、重试。

## 7. 11 类算法实现细则

| 算法 | 实现组合 | 必须暴露的关键参数 | 事件确认与抑制 |
| --- | --- | --- | --- |
| 安全帽 | Person + Helmet/PPE | personConf、helmetConf、unknownPolicy、N/M 帧 | 先确认 person；unknown 不强判违规；按 trackId 冷却 |
| 反光衣 | Person + Vest/PPE | personConf、vestConf、ROI、N/M 帧 | 多帧稳定后“未穿反光衣” |
| 吸烟 | Person/hand/face + Smoking | confidence、duration、N/M、cooldown | 禁止单帧；同一 trackId 聚合 |
| 打电话 | Person + Phone/pose/action | confidence、duration、N/M、cooldown | 手机靠近耳部持续确认，过滤持物动作 |
| 人员闯入 | Person + Tracker + Schedule | schedule、duration、cooldown | 非允许时间出现人员并持续 |
| 区域入侵 | Person/Vehicle + Tracker + ROI | pointMode、overlap、duration、N/M | 进入多边形且满足规则，同 trackId 只保留一个活动事件 |
| 跌倒 | Fall model + Tracker | duration、N/M、aspect/pose 辅助阈值 | 区分蹲/坐/弯腰/躺卧，持续确认 |
| 火焰 | Fire detector | confidence、minArea、N/M、cooldown | 无 trackId 时按 Camera+Task+Type+窗口聚合，抑制红光干扰 |
| 车辆 | 自研 Vehicle Detector + Tracker | classFilter、confidence、ROI | 作为独立能力及车牌前置结果复用 |
| 车牌 | Vehicle/Plate + OCR | ocrVoteFrames、minVotes、country/plateType | 多帧投票稳定输出 plateNumber/Color/Confidence，同车短时不重复 |
| 人员离岗 | Person + Tracker + Job ROI | minPersonCount、absenceDuration、schedule | 岗位人数低于阈值并持续，恢复后关闭 |

算法验收不能只看单张 mAP；必须同时统计事件级 Precision/Recall、每路每小时误报、漏报、端到端延迟、资源占用和冷却去重正确性。

### 7.1 预置模型资产验收

除 11 类核心算法外，V1.0 还必须完整纳入 EasyAIoT 的 12 个内置模型：Safety Helmet、Sleeping on Duty、Person Detection、License Plate、Reflective Vest、Flame、Smoking Detection、Phone Call Detection、Road Waterlogging、Face Mask、Fall Detection、Face Detection。

- 破坏性操作明确对象、影响、是否可恢复；模型回滚、节点升级、批量停任务必须展示影响清单。
