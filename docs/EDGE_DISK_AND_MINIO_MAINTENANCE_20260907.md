## 证据存储修复

1. Runtime 只在证据生成结束、Agent 已获得所有应上传媒体的成功响应后接收确认。
2. 确认待上传事件时，在同一 SQLite 事务中写入待清理文件记录。随后删除本地媒体；重启或临时删除失败会重试。
3. 清理仅接受当前事件目录中的 `snapshot.jpg`、`evidence.mp4`，不递归删除、不跟随符号链接，不清理仍被待上传事件引用的文件。
4. Agent 遇到空文件、缺失文件或上传异常时不确认完成，不丢弃本地证据。
5. 控制面修复旧媒体记录的重试：旧版本曾复用同一对象地址；补传成功后必须更新旧记录指向新的内容寻址对象，才能返回成功。存储失败时不能因为旧行存在就假报成功。

历史文件逐个对比本地 SHA-256、媒体元数据和从 MinIO 下载的原始字节。首次核验 1,073 个文件中 958 个匹配。另 55 个可关联文件已在控制面修复后通过节点原有媒体接口补传，并通过下载核验；已上传的历史本地副本均已清理。5 条旧运行遗留的未结束交付，在确认运行已结束、剩余文件均在 MinIO 校验成功后，调用 Runtime 证据存储与确认流程完成收尾；没有伪造缺失录像。

还有 30 个历史事件目录（60 个文件）在平台查不到事件记录，未伪造事件关联。其原始文件已完整归档至 MinIO：`ai-video/recovery/node-1/20260907/unlinked-evidence-20260907.tar.gz`，基础文件编号 `336385`，下载校验成功。恢复清单见 `unlinked-evidence-archive.json` 回执。
