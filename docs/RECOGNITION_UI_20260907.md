## 原因与修复

1. 原实时页的主区域仅播放视频，识别藏在侧边小图。视频墙默认关闭 Overlay，且旧框只保留 750 ms，小于当前分析耗时。现改为明确的主识别模式，图片与坐标配对；不会把迟到框贴到当前视频上。
2. 实时推送逐条在 WebSocket onMessage 中路由，避免观察单一最后消息值时，多播放会话的连续推送互相覆盖。实际验收了实时页和视频墙同时接收识别。
3. 事件详情原本直接展示目标、规则 JSON，且未在截图上绘框。现将归一化坐标叠加在告警截图上，安全帽使用实际 PPE 头部框；旧数据缺坐标时明确说明。
4. 短暂漏检会重置规则确认计时，原代码在冷却后可能再次发出同一活动的 ALARM，重写本地截图。现同一活动只确认一次，恢复关闭后才开始新活动。
5. 服务端此前按同一个事件目录和 snapshot.jpg/evidence.mp4 存储不同内容，文件配置关闭随机后缀，导致证据被覆盖。新文件使用 SHA256 前缀；相同已送达内容重试不重复写入存储。历史对象键比较剔除签名查询参数，不把失效原图当作有效目标证据。
6. 原分析循环等待录像编码完成。现采用容量 4 的后台编码队列、单个编码消费者、veryfast 和单线程编码，分析不再等待录像打包；停止时排空队列后关闭存储。
