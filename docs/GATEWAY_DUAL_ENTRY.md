# 网关独立运行与平台双入口

同一台网关支持平台工作台和本地网页同时访问，没有托管/独立切换开关。模型推理、执行配置、任务期望状态和本地证据都在设备上，关闭网页或停止中心平台不会停止已保存的网关任务。

## 使用入口

- 平台：边缘节点列表 → **网关工作台**；任务运行监控也提供入口。读取由节点查询权限控制，修改同时需要节点操作与任务修改权限。
- 本地：`http://网关IP:48901`。使用独立的设备管理密码，不需要中心用户登录。平台管理员可在工作台设置本地密码；首次安装也会生成仅设备用户可读的 `/var/lib/linsight/runtime-data/gateway/local-password`。密码更新使原有本地会话失效。
- 本地页面右上角提供“平台连接设置”。可填写平台 IP、`IP:端口` 或完整 HTTP(S) 根地址，先调用平台专用探针确认目标身份，也可在平台暂时不可达时保存。配置以 `0600` 权限原子写入 `/var/lib/linsight/runtime-data/gateway/platform-connection.json`；Edge Agent 在约 1 秒内重建中心连接，本地推理任务与 Runtime 不重启。该能力适用于同一平台地址或端口变更；迁移到凭据不互认的新平台仍需重新注册节点。
- Runtime 内部接口仍仅监听 `127.0.0.1:48900`，同一 Python 进程自动提供 `0.0.0.0:48901` 本地管理入口。网页登录后经进程内 ASGI 调用网关接口，不持有 Runtime 密钥。需要 HTTPS 的现场通过受信任证书的反向代理接入本地管理端口。
- 事件订阅另由同一 Runtime 进程监听 TCP `48902`，默认停用，需在「事件接口」生成密钥并启用。业务客户端按 [TCP 事件协议](GATEWAY_EVENT_DELIVERY.md) 连接；此端口不提供 HTTP 网页。

## 已有平台任务

升级后由平台启动一次任务，网关自动保存完整执行配置。随后可从任一工作台调整模型绑定、置信度、分析帧率、时序参数、摄像头地址、ROI 与规则，或启停任务。保存运行配置会短暂重启该任务；共享摄像头不能配置互相矛盾的源地址。

平台和本地工作台都直接读取网关实际版本。中心任务配置仍表示发布/编排意图，运行上报额外携带 `gatewayRevision`、`gatewayAppliedRevision` 和不含摄像头凭据的 `gatewayConfiguration`；任务监控提供网关工作台入口。中心资产目录、跨节点编排和人工事件处置仍由平台负责。

网关实际配置以独立递增版本保护：编辑携带 `expectedRevision` 与 `requestId`；旧版本返回冲突并保留页面草稿。同一请求重放不再次执行。平台命令在入队时将观察到的网关版本固定在幂等键内，断网期间的旧命令不能覆盖后来发生的本地修改。平台再次启动同一 `configVersion` 使用网关已保存的执行配置；发布新的中心配置版本仍须通过网关并发校验。

本地保存仅提交网关执行配置，不携带平台入口用于解析摄像头码流的 `platformManaged`、`streamTypeChanged` 标记。2026-09-24 修复本地编辑因这两个多余字段被严格校验拒绝的问题：新版页面按入口组织请求；本地接口兼容旧页面的普通保存，任务归属始终取设备已保存的配置。旧页面若声明切换码流，则明确提示使用平台选择或本地高级设置中的 RTSP 地址，不静默忽略切换意图。其他非法字段、版本冲突和幂等校验继续有效。升级需包含 Runtime 与网关控制台制品，无数据迁移。

### 本地切换主、子码流（2026-09-24）

平台与本地均可在“编辑算法配置 → 识别参数 → 识别码流”选择主/子码流并保存。
设备支持 `task.stream-switch.v1` 时，由同一网关保存接口从本地已加密保存的两路地址中选择实际 `sourceUrl`，无需连接平台。
运行任务保存后短暂重启，已停止的任务保持停止；识别参数、区域、模型绑定与任务身份不随切换改变。
同一摄像头仍共用拉流所有者，其他任务存在相冲突的源地址时明确拒绝保存，不隐式修改其他任务。

Java 的任务启动明细新增可选 `streamUrls`（`MAIN`/`SUB`），Agent 只在有值时转发。
平台从摄像头领域查询已配置的地址，Runtime 将地址随任务配置加密落盘，快照与心跳仅返回可用类型和实际选择，不返回地址或凭据。
平台网关编辑旧任务时，在缺少两路地址的情况下通过 `syncStreamUrls` 请求补齐；该标记由 Java 校验任务/摄像头/节点归属后剥离，预检与保存使用相同解析。
既有本地任务也可在“高级设置”填写主/子码流 RTSP 地址，空白表示保留。地址缺失或无效时拒绝切换并保留原配置。
新部署的任务自动携带已配置的两路地址；旧盒子需同时升级 Java、Agent、Runtime 和控制台，之后在平台保存一次任务配置，或在本地填写缺少的地址。
同一 `configVersion` 的平台重启只补齐缺失地址，不覆盖已保存的本地选择和地址；旧版本编辑、重复请求仍由原版本/幂等机制处理。
无数据库迁移。回滚至不认识 `streamUrls` 的 Runtime 前，须备份设备配置并经受控迁移去掉该新增字段，保留当时选中的 `sourceUrl`；不能直接回滚旧解析器并声称配置兼容。

### 区域模板与实际告警区域（2026-09-22）

规则中心保存可复用的区域和告警条件模板；网关“配置参数 → 告警条件”编辑当前摄像头实际使用的配置。无需在两处重复绘制：可直接在网关绘制，或在平台网关点击“从规则模板复制区域”，选择已发布模板、版本和区域后复制到当前区域。复制只带入形状，保留当前任务的目标类别、判断点与其他告警条件；使用前应对照当前摄像头画面确认位置。

两处画布均支持四边形、多边形、拖动白色顶点、拖动区域内部整体移动及撤销/重做。截图仅作绘图背景，不随模板持久保存；未载入截图时仍可查看已有顶点。复制、绘制与拖动先修改草稿，点击保存识别配置后才应用到网关。发布模板不会自动替换运行任务。本地离线入口使用相同画布，不依赖中心模板目录；已有网关本地页面需通过正常升级获取新版静态资源。

“显示识别区域”按每个算法单独控制：告警区域工具栏只影响当前编辑的算法；实时预览算法卡片和网关详情视频图层栏各自提供对应算法的开关。开启后，视频用黄色虚线显示该算法已应用的区域；关闭只隐藏该算法的边界，其他算法保持原状态。绘图区保持可见、可拖动，识别与告警继续按原区域运行。该显示偏好立即保存，不需要确认任务配置。平台按租户、账号、摄像头及算法任务保存，本地独立保存；切换识别标注不影响区域边界的显示。

摄像头能力响应的 `regions` 只投影网关上报且 `gatewayRevision == gatewayAppliedRevision > 0` 的区域 ID、名称和归一化顶点，并核对 taskId/cameraId；不返回完整执行配置，不使用已发布模板替代实际区域。既有 `display-preference` 接口的 `hiddenLayers` 使用 `roi-task-{taskId}` / `roi-entry-{entryId}`，与标注图层键独立，无数据库迁移。旧全局键 `recognition-regions` 保留 API 兼容，新页面忽略并在下次保存时移除；未单独配置的算法默认显示区域。平台服务与前端须同步更新，本地网页通过控制台制品正常升级。

## 上传图片验证识别（2026-09-22）

平台网关详情“识别算法”或本地工作台的任务操作列提供 **图片识别**。
打开任务弹窗，上传静态 JPG/PNG/WebP 后点击“开始识别”。支持最大 4 MiB、1600 万像素，
保留原始分辨率并按 EXIF 校正方向；可查看识别框、目标列表、置信度、车牌文字和耗时。
当前网关保存了配置且模型已部署时，已停止的任务也可验证，不需要启动摄像头。

平台调用 `POST /admin-api/ai-video/node/gateway/image-test`，权限为
`ai-video:node:query` + `ai-video:model:test`；经已有节点/租户鉴权通道转发
`task.recognize-image`，请求只接受 `taskId` 与 `imageBase64`。本地入口复用登录会话和同一 RPC。
客户端不能携带模型路径、摄像头地址或替换执行配置。图片和返回结果不记入 API 日志。
设备端从保存的配置取得 Pipeline/算法包和模型，复用 ModelPool 租约，单网关只运行一个图片测试，
等待期限 90 秒。图片仅在本次处理期间使用，临时目录在结束或失败时删除。

每次测试使用新建的跟踪、OCR 投票和算法包实例，不改变运行任务的状态或事件。
车牌列表的文字是本张图片的 OCR 结果；`PENDING` 表示尚未满足视频多帧确认，不能当作正式识别事件。
离岗、停留、人数变化等时序判断需要视频；本功能不代替现场准确率验收。

部署顺序：构建网关控制台制品（`make gateway-console`），更新 Java 控制面，再在线升级目标网关的
Runtime 与 Edge Agent。`snapshot.capabilities` 中的 `task.image-recognition.v1` 表示支持，
旧版本弹窗提示升级且禁止提交。Agent 接收消息上限扩展为 6 MiB，以容纳 4 MiB 图片的 Base64 编码，
设备仍独立校验图片字节数与像素数。回滚时同步回滚平台与网关版本，无数据库迁移。

本次验证：11 项图片 Runtime 测试、60 项既有任务/车牌/网关/隧道回归、9 项 Java 网关测试、
4 项 Vue 图片交互测试通过，TypeScript、ESLint、Ruff 和正式控制台构建通过。
独立本地网关浏览器验证了约 1.7 MB PNG 上传、实际 ONNX 执行、框与表格同步显示；
ONNX 使用确定性契约模型，该证据只证明接口和展示链路，不代表现场算法准确率。
现场运行网关未在本次开发验证中升级。

## 从网关直接配置

本地工作台可导入 ONNX / RKNN 模型及对应执行配置，SHA256 在设备端计算；提供来源 SHA256 时还会逐字节校验。模型版本不可覆盖，导入时需要匹配设备硬件、预处理与输出解码契约。平台原有模型中心的部署方式继续可用。

在工作台点击“创建识别任务”，选择本机模型、填写摄像头地址和识别参数，保存后主动启动。新任务默认是通用目标检测，可启用区域/时序告警；已有平台算法的完整 Pipeline 则通过平台下发复用。高级模型绑定、复杂规则结构继续提供 JSON 编辑入口，普通 ROI 可直接在识别截图上绘制。

本地创建的任务通过平台**网关工作台**同样可见、可编辑；它们不冒用中心目录的任务/模型身份，不自动注册到中心任务目录或中心事件处置库。网关工作台查询本地事件、截图和录像，不依赖中心目录登记。平台下发的任务继续按原协议同步事件与证据。

## 重启、故障与存储

- Runtime 按加密保存的期望配置恢复任务，仅从本地模型注册表校验、加载任务实际依赖的模型，过程不依赖 Agent 注册、心跳或中心下载地址。Agent 不再遍历预热所有历史模型版本。
- 模型缓存默认 4 个槽位。任务启动时一次性预留全部模型，多个任务共享同一模型时累计占用；停止、失败后释放。推理尚未完成的模型也不会被淘汰。缓存只淘汰闲置模型；任务超过可用容量时返回 `MODEL_CAPACITY_EXCEEDED`，本地模型缺失或校验失败时返回 `MODEL_UNAVAILABLE`，平台同步显示处理提示。
- 配置保存会展示只读容量预检，启动前强制再次预检。预检按当前节点、实际运行中任务和共享模型去重计算槽位与内存预算；默认超过 4 槽位，或预计启动后无法保留 5%/至少 512 MiB 安全内存时拒绝启动，并返回冲突任务/模型。每个唯一模型按已校验制品的 2 倍、最低 64 MiB 估算；预检不加载/淘汰模型，也不改变中心或网关任务状态。
- 停止意图同样落盘，已停止的任务不会重启复活。配置保存和实际应用分别显示版本；模型损坏、设备不可用或断流会显示待恢复状态并重试。
- SQLite WAL 保存网关配置与幂等记录；摄像头地址所在的完整配置使用设备密钥加密，不能丢弃 `configuration.key` 后只恢复数据库。
- 事件上传 ACK 与本地历史分离。已同步事件、本地创建任务的事件默认保留 7 天，可用 `LINSIGHT_RUNTIME_GATEWAY_HISTORY_DAYS` 设置 1–365 天。
- 平台下发任务的未同步证据继续遵守“不在上传确认前删除”的原有保证；长期停用中心时需关注磁盘与离线积压指标。保留期不会静默丢弃这些待补传证据。
- 录像本地按 HTTP Range 播放；平台工作台通过有界分片获取本地录像，浏览器预加载上限 128 MB，大录像可直接在本地入口播放。

## 构建和部署

使用项目要求的 Node.js 22.18+ / 24 与 Corepack：

```bash
bash scripts/build-gateway-console.sh
```

该脚本构建现有 Vue 应用的独立 `gateway.html` 入口，并生成独立的内容寻址制品：

- `runtime/gateway-console/manifest.json`：记录 Schema、前端源码摘要、制品 SHA256、大小和逐文件摘要；
- `runtime/gateway-console/gateway-console-<sha256前12位>.tar.gz`：使用固定元数据生成的不可变静态资源包；
- `runtime/gateway-console/current/`：经同一 manifest 校验后原子展开的本地运行副本。

上述目录属于构建输出并由 Git 忽略，不再提交数百个带 hash 的 JS/CSS 文件。控制面生成节点部署包时
要求 manifest 和制品同时存在、先复算 SHA256，再将二者纳入 Runtime 包。节点在停止旧服务前使用
标准库安全解包，复核逐文件摘要，并原子安装到 `gateway-console/current/`；任一校验失败都不切换服务。

启动方式保持原样，只需启动 Runtime：

```bash
bash scripts/start-runtime.sh
```

2026-09-09 起，本地网页随 Runtime 生命周期自动启动、恢复和关闭，不再安装 `linsight-local-console.service`。已有节点通过平台正常在线升级完成迁移；安装器在备份后自动停用旧网页服务，避免争抢端口，回滚时恢复旧服务原来的启用状态。设备数据目录和本地密码保留。

安装器必须验证 Runtime 健康、`48901/gateway-health` 的 `owner=runtime` 及网页首页可访问，才允许进入部署成功确认。页面资源缺失或端口占用会使启动明确失败；异常退出的网页监听由 Runtime 自动恢复。局域网只暴露已有鉴权网页接口，`/v1/**` 不从 48901 提供访问。

默认无需配置额外参数。开发或测试可用 `LINSIGHT_RUNTIME_GATEWAY_CONSOLE_HOST`、`LINSIGHT_RUNTIME_GATEWAY_CONSOLE_PORT` 覆盖监听地址；`LINSIGHT_RUNTIME_GATEWAY_CONSOLE_ENABLED=false` 仅用于明确不需要网页的环境。正式节点部署健康检查要求默认 48901 入口。旧 `scripts/start-gateway-console.sh` 仅保留为启动 Runtime 的兼容入口。

控制面打包的 `runtime-source-dir` 默认使用 `auto`，从启动目录向上定位包含 `backend/pom.xml` 和完整 `runtime/` 的项目根目录，兼容从根目录、`backend/` 和 `backend/linsight-server/` 启动。`start-backend.sh` 会设置绝对路径；独立部署的控制面可显式设置 `LINSIGHT_NODE_DEPLOYMENT_RUNTIME_SOURCE`。显式路径无效时直接报错，不回退到其他源码。预检离线依赖与正式打包使用同一个路径解析结果。

## 验证边界

工程验证覆盖版本竞争、幂等、旧命令拒绝、重启恢复、停止持久化、实际 ONNX 会话重建、事件 ACK 后本地可读、保留期、登录/CSRF/密码失效和平台租户路由。浏览器验证使用隔离 Runtime、真实 ONNX 推理与生成的 H.264 测试视频，不接触现场摄像头。

这些验证不替代现场网关断电、真实摄像头、硬件推理兼容性与长期磁盘容量验收。已有现场节点需要部署新版软件后才能使用双入口。


### 统一管理入口（2026-09-09）

平台路径为“边缘计算 → 边缘网关卡片 → 网关详情 → 识别算法”。摄像头能力和任务中心的管理按钮携带 nodeId/cameraId 定位该页；平台已移除分散的直接启停及保存即启动按钮。详情整合模型、事件、日志、部署历史和设备操作。入口识别配置保存保留原启用状态，启停在统一列表操作。现场工作台继续支持脱离平台访问。

模型卸载新增 model.uninstall.v1 能力与 UNINSTALL_MODEL 耐久命令。旧网关保留原有安装和识别能力，但卸载按钮禁用并提示在线升级；不要求安装额外服务。卸载删除注册信息和对应制品文件，保留任务配置、历史事件、平台模型版本和其他网关模型。启用任务、入口识别或在用模型租约会阻止卸载。模型文件移除后的任务必须重新安装才能启动；失败/超时回执不视为已卸载。

实时画面复用视频监控的 PPE 结果解释：`person` 对象上的 `helmet` / `vest` 属性决定佩戴状态，已确认结果使用 PPE 检测区域和置信度；未知状态显示“安全帽待确认”或“反光衣待确认”，不把人员检测置信度作为佩戴结论。2026-09-09 修复工作台只显示原始 `person` 标签的问题，6 项结果展示测试、类型检查、ESLint 和网页构建通过；平台实际现场画面验证了“未戴安全帽”和“安全帽待确认”。独立入口资源已重新打包，已有网关通过正常在线升级获取。

### 统一实时视频与识别框（2026-09-09）

实时预览、平台网关工作台及本地工作台共用 `CameraPreviewPlayer`、`SynchronizedRecognitionVideo` 和 `PreviewOverlay`。网关工作台不再每 1.5 秒刷新 JPEG，视频通过 WebRTC 连续播放，结果只传递检测元数据，通过同一源流的 `streamId/sourcePts` 对齐视频。视频帧率与算法分析帧率分别计量，算法低帧率不会把视频降为截图轮播；源时间信息不匹配时不会将旧框强行贴到新画面。

两处默认只展示需关注的异常目标，开关可展开合规与待确认目标；佩戴状态、颜色、框选位置及坐标缩放遵循同一结果解释。“识别 ROI”可独立显示或隐藏识别框，不停止视频和算法。该开关控制结果叠加，不修改任务的区域规则配置。

信令通过 `preview.open/status/close`，轻量结果通过 `preview.frame`。Runtime 复用既有 WebRTC 管理器和摄像头流；任务源地址从网关持久配置读取，不接受浏览器覆盖。每个会话绑定任务，结果按任务、运行批次、摄像头及会话校验。平台调用同时要求节点查询和摄像头预览权限；本地调用使用现有设备登录会话，不依赖平台登录。没有 `preview.webrtc.v1` 能力的旧节点提示在线升级。

### 刷脸配置按网关隔离（2026-09-09）

入口刷脸在“网关详情 → 识别算法 → 添加识别算法”选择摄像头后配置。所属网关由详情页固定，只读展示；模型选项仅包含该网关已部署且 READY 的刷脸模型。同一摄像头可在不同网关分别配置模型、人员范围、ROI 和阈值，启停互不影响。

入口列表支持 cameraId/nodeId 联合过滤。编辑按明确 entryAccessId 与当前网关、摄像头匹配，不回退到其他网关的配置；保存禁止改变已有记录的 nodeId/cameraId，并保留配置版本校验。启用、停止、删除、值守状态接口支持 nodeId 归属校验，保留旧调用参数兼容。现有记录保留原 ID、网关、版本和参数，不需要数据迁移或重复创建。

只有刷脸配置的网关也显示本机入口预览，复用 WebRTC 和刷脸 ROI 图层；不再把“没有普通视频任务”显示成“没有识别任务”。本次修改更新平台表单、预览及控制面校验，未改变 Runtime/Agent 部署协议。


### 识别任务删除同步（2026-09-20）

移除的是当前网关上的识别任务配置；算法库、模型资产、运行历史和历史事件继续保留。平台删除所有已下发任务（包括 Pipeline 和算法包）时，先通过 `task.remove` 校验网关版本并移除设备配置，成功后再逻辑删除中心记录。

本地入口移除任务时，Runtime 在同一 SQLite 事务内删除配置并保存加密的 `task_removal` 记录。删除版本为被删除配置版本加一，包含原任务、运行批次、配置版本和请求 ID。`task.removal.sync.v1` 表示设备支持此协议；删除记录长期保留以拒绝迟到启动命令与同 ID 重建，不随事件保留期清理。

Agent 通过内部 `task-removal.list` 读取未确认记录，使用节点凭据调用 `POST /node-api/ai-video/task/removal/report`。任务域校验租户、节点、已知运行批次、配置版本和递增的网关版本，更新审计快照并逻辑删除任务；重复上报已删除任务返回成功。中心提交成功后，Agent 调用仅平台来源允许的 `task-removal.ack`。断网、进程重启、上报或 ACK 丢失都会重试，不依赖中心扫描缺失任务。本地独立创建的任务不删除中心任务，删除后其本地事件归属也保持不变。

旧版升级自动扫描 `mutation_receipt`：仅当配置已不存在且回执指纹严格等于 `SHA256(remove:{taskId}:{revision})` 时恢复删除记录，再从该任务较早的 `platform-start:{runId}:{configVersion}` 回执恢复中心归属。没有删除回执的缺失配置、未下发草稿和离线设备不被推断为已删除。无需直接修改数据库或重新配置现场算法。

节点上报不具有管理员登录身份，中心逻辑删除必须将 `edge-agent` 审计操作人显式传给 MyBatis，避免 `updater` 非空约束导致事务回滚。2026-09-20 已在 192.168.2.17（nodeId=1，部署任务 69，source-9d76961363b7）验证旧回执恢复、两端列表同步、重复删除/上报、旧启动拒绝及 Runtime/Agent 重启；最终两端均为 0 个任务。现场证据位于 `artifacts/gateway-removal-20260920/`。

### 统一已有算法的编辑流程（2026-09-22）

平台“网关详情 → 识别算法 → 配置参数”和本地工作台的已有视频任务统一使用“编辑算法配置”窗口。厂区车辆等 Pipeline 与安全帽等算法包共用三个页签：识别参数、告警条件、高级设置。前者包含名称、置信度、分析帧率和算法专用字段；告警条件包含当前任务的 ROI 与确认条件；高级设置包含当前算法声明的模型角色、源地址和规则 JSON。统计型算法明确显示无需配置告警条件。

编辑前重新读取网关快照，以实际任务参数和网关 revision 为准；离线、读取失败或任务已移除时不回退到中心旧记录。已有任务不进入创建/部署向导，不重新选择算法或创建任务。新建任务仍由部署入口准备依赖，入口主动刷脸继续使用其所属领域的配置入口。

算法包的字段、默认值和模型角色取自已部署版本的 manifest；旧 Pipeline 按能力契约适配为同一参数表单。保存时算法包专用值写入 `parameters.algorithm`，旧 Pipeline 专用值写入原有顶层位置，保留未编辑字段与嵌套扩展值。人员资源使用网关已同步的人员库和选择范围，不从平台目录替换本机资源。

保存共用 `task.capacity.preflight` 和 `task.save`，保留任务身份、运行批次、模型绑定、ROI、启用状态、expectedRevision 校验和请求幂等键。运行中的算法保存后由网关按既有协议短暂重启；并发版本冲突展示错误并保留草稿，不自动覆盖。区域显隐继续按当前算法独立控制实时预览和网关详情，绘图区不受影响。

验证记录见 [统一算法编辑验证](evidence/unified-algorithm-editor-20260922.md)。平台开发页面即时使用新表单；现有盒子的本地网页需安装重新构建的控制台制品后获得同样界面。

### 本地登录与工作台布局（2026-09-23）

独立入口采用居中登录页与响应式工作台；顶部保留平台连接和退出入口，任务状态与主要操作归入同一标题区。事件接口和任务投递弹窗使用全宽选择器，小屏改为单列表单，网络鉴权、超时重试和位置信息分组展示。

本地管理密码允许 6–256 位，不要求字符组合；前后端统一校验，修改时确认两次输入。已有密码保留不变。登录使用 HttpOnly / SameSite=Strict Cookie，HTTPS 下设置 Secure；会话有效期为 30 天，有效访问至多每天续期一次。会话摘要保存在设备数据目录 `gateway/local-sessions.sqlite3`（权限 0600），仅保存随机令牌的 SHA256，服务/设备重启后可继续使用。主动退出撤销当前会话；修改密码会使旧会话失效。原内存会话无法迁移，首次升级后需登录一次。

`GET /gateway-api/session` 仅检查本地登录，不依赖推理服务快照；推理服务暂不可用不会导致重新登录。真正的 401 会回到登录页。网关在线升级需同时带上 Runtime 与新控制台制品，现有配置和任务不需要迁移。
