## 测试发现并修复的问题

1. 原规则引擎即使配置 CAMERA_TASK_TYPE，仍按多个 tracker ID 独立确认，回放产生 5 条告警（674–678）。现对场景存在性规则先按 ROI/类别筛选，再每帧选一个真实候选进入共享状态；跨 trackId 和去重时间桶持续出现仍只告警一次。COUNT 规则维持场景计数，停留/徘徊维持轨迹计算。恢复快照保留最后一次真实类别和目标，避免将烟雾变成人员快照。
2. RTSP 源消失时 PyAV HTTPNotFoundError 不继承 OSError，原循环没有捕获，停止任务随之报错。补充 FFmpegError 重连处理；取消等待中的 av.open 失败时保持取消语义，正常释放资源。
3. 停用测试摄像头触发编辑接口 500：CameraDO 使用 @Version，但 MyBatis 拦截链未启用现有 OptimisticLockerInnerInterceptor，更新 SQL 缺少 MP_OPTLOCK_VERSION_ORIGINAL。启用该插件并验证它为真实版本实体注入原版本、递增新版本。

验证：Runtime 相关测试 59 项通过；Java 摄像头服务 5 项、事件服务 11 项、版本参数回归 1 项通过，受影响 Maven reactor 打包成功。Python 修改文件 Ruff 检查通过。
