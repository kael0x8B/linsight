# ADR：盒子 TCP 事件改为实时订阅与图片 URL（V3）

- 日期：2026-09-24
- 状态：已按用户要求实施
- 影响范围：AI Runtime 网关事件流、网关 HTTP 图片入口、工作台协议展示、Java Netty 示例客户端

## 背景

原 V2 接口允许以游标补读历史，在 TCP JSON 中携带 Base64 图片。接入方要求取消游标，只接收实时事件，并通过 HTTP 地址获取事件图片，同时明确事件字段及车牌字段。

## 决定

1. 握手版本提升至 `3.0`；保留 challenge + HMAC + subscribe，`subscribe` 只接受 `taskIds` 和 `eventTypes` 过滤。订阅确认时以网关内部最新事件序号为起点，之后才发送新事件。断线后重新订阅仍从当时的新事件开始。
2. TCP 事件不包含 `cursor` 或 Base64 图片。图片字段包含 `url`、`contentType`、`sha256`、`expiresAt`。网关工作台 HTTP 服务增加无登录 Cookie 的只读图片路由，以订阅密钥 HMAC 签发有效期 1 小时的 URL。密钥轮换或停用订阅使旧链接失效。
3. 图片内容仍由事件域的本地证据存储持有；HTTP 路由先校验签名，再通过事件存储的受限路径访问截图。TCP 内部事件表继续作为实时轮询与证据保留的实现细节，不对客户端开放历史查询。
4. Java 客户端在业务处理前下载图片并核对 SHA-256，按 `sourceEventId` 做幂等处理。协议文档用中文逐项说明事件字段，特别标明 `data.result.attributes.plateNumber` 是最终确认车牌号。

## 影响与迁移

V2 客户端不能直接连接 V3 服务，需与 Runtime 同步升级。原 SQLite 事件表和旧 HTTP 投递记录保留供迁移核对，不自动补送给 V3 订阅者。客户端断线期间的事件不会通过 TCP 补发；需要可靠历史消费的接入方须另用平台事件链路或网关历史接口。除 TCP 48902 外，客户端网络还须放通图片 HTTP 端口 48901（或现场配置的端口）。默认 URL 使用 TCP 连接在盒子上的本地 IP；如经代理访问，须确保客户端能访问该地址。

## 安全与回滚

图片 URL 是短期访问凭据，不应长期公开；默认 HTTP 明文只用于受控网络，公网场景需 TLS 代理。保留原有网关管理登录保护，签名图片路由只接受快照 UUID 和有效签名。回滚 V2 需要同步回滚服务端和客户端；V3 产生的实时事件不会变成 V2 的历史补读承诺。

## 验证

覆盖 HMAC 握手、只收订阅后的事件、任务和类型过滤、事件无游标和 Base64、图片 URL 无登录下载、错误签名拒绝、密钥轮换断开连接，以及 Java 17 客户端构建。
