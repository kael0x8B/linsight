# ADR：盒子通用事件定向投递

- 状态：2026-09-20 用户确认方案并授权开发。
- 范围：盒子通用事件接口、任务绑定、事件类型过滤；本次增加车牌算法场景。
- 用户明确纠正：通用平台不可变成车牌专用界面。算法创建归算法模块，通用投递列表不固定展示车牌或料仓字段。

## 决策

在现有 Runtime 网关进程内增加事件投递工作协程。接口、凭据和路由属于单盒子的执行配置，平台工作台和盒子本地入口操作同一份数据；继续使用设备密钥加密和 SQLite WAL，不新增服务或数据库产品。

只有明确绑定接口的任务产生的事件进入该盒子的投递队列，可进一步按事件类型过滤；未绑定任务不发送。投递器不判断算法种类，也不承担 OCR 确认职责。事件创建与投递记录在同一个本地事务持久化，记录事件发生时的位置、摄像头、算法结果和目标接口版本快照。截图就绪即可发送 JSON，JPEG 以 Base64 随请求提交，不要求接收方反向访问盒子。接口支持公网 HTTPS，以及显式声明的内网 HTTP/HTTPS 和端口。

盒子投递、同步平台、平台 Webhook 是独立消费者。任一消费者 ACK、失败、停用都不能确认或取消另一消费者；平台 Webhook 继续遵守既有订阅和开关。两侧携带相同 sourceEventId，接收方可按需要跨链路去重。盒子投递至少一次，接收方须幂等；重试和人工重放不改变业务事件身份。

媒体保留以持久化消费者引用保护，盒子未投递成功（包括死信）的截图不能因平台 ACK 或本地历史保留期被清除。配置修改不将已有待发消息改投新地址；接口停用会暂停该接口的积压，重新启用后继续。

## 实现与验证边界

复用既有 Vehicle/YuNet/LPRNet Pipeline，在算法配置中增加车牌模板、OCR 置信度/时间窗口和已确认候选门槛。事件接口复用通用结果快照。同车在一次到访中以稳定车牌身份去重，离开并达到恢复时间后可以产生新事件。现场准确率、夜间与灰尘效果仍须使用真实视频验收。

验证本地与平台配置权限、并发版本/请求幂等、按任务隔离、无绑定不发送、投递失败/恢复/重启、截图保留、平台同步互不干扰、车牌多帧确认、离开再进入以及页面构建和真实浏览器操作。

## 迁移与回滚

本地数据库只增加表和索引，既有配置和事件保持兼容；新能力通过 capability 声明展示。升级前备份 runtime-data（包括 configuration.key）。回滚前停用新路由并处理或导出尚未成功的投递记录及截图；老版本不会执行新投递队列，不能宣称回滚后仍会自动补发。
