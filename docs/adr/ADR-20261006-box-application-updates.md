# ADR：盒子应用离线升级与首次迁移

- 日期：2026-10-06
- 状态：按用户批准的方案实施；现场硬件验收待补充
- 所有者：node；沿用 Java 控制面、Runtime/Agent 与现有网关鉴权通道。

## 决策

发布包含 Runtime、Agent、控制台、独立 Python 与锁定 wheel 的 `.lup` 文件。Ed25519
签名绑定完整清单，盒子只安装受信公钥。每个应用版本和依赖安装到独立目录，保留上一版本。
不修改系统 Python、APT、驱动或业务数据。首版只接受数据格式向后兼容的版本。

独立 root 安装器使用固定 Unix socket；Runtime/Agent 以原服务用户连接，不能传入任意
执行命令、目标路径或验签公钥。CLI、本地管理会话和平台 node:upgrade 权限入口共用协议。
平台复用既有节点鉴权隧道按有界分块传输，支持相同上传 ID 续传；只有完整包验签成功、
预检完成且用户点击安装后才切换。升级任务在设备落盘，不依赖 HTTP 请求和中心心跳存活。

安装器与现有 SSH 部署共用 `/run/linsight-deploy.lock`。切换前持久记录旧指针，启动失败
恢复旧指针；开机恢复先于业务服务。自动回滚不恢复旧事件数据库，避免丢失新增事件。
升级成功以本机服务、真实版本、网页及原正常任务恢复为准，中心断线只影响结果查询。

## 首次迁移

通过受信 SSH/本地终端安装 root 持有的独立安装器、运行环境和公钥。旧 Runtime/venv
路径保持可运行，记录为 legacy 基线；systemd drop-in 使用稳定启动器选择版本。
迁移不覆盖设备 env、身份、配置密钥、模型、事件、期望任务状态。缺少有效旧服务时拒绝迁移。
新的完整包安装成功后才能向用户报告应用升级完成。

已迁移设备的旧 SSH 覆盖式部署必须拒绝执行，避免删除作为回滚基线保留的目录；后续使用
完整包入口。旧 Agent 签名包入口也不能再修改完整应用版本。

## 备选、兼容与验证

继续直接覆盖源码无法可靠回退依赖；引入容器部署会改变现场 NPU/视频设备接入方式。
采用版本目录可复用现有 systemd 与 Python 基础。新增协议均使用 `app-upgrade.*`，
旧节点不支持时只提示首次迁移，不下发破坏性兼容动作。安装器自身更新不混入应用包。

本机 Docker Linux 模拟盒子验证签名、续传、磁盘不足、重复请求、并发锁、准备失败、
切换失败、进程中断、容器重启、离线本地入口和回滚后数据保留。真实断电、RKNN/MPP/RGA
及现场识别恢复仍需要目标硬件证据，模拟结果不能冒充客户现场验收。


## 平台生成入口补充（2026-10-06）

用户要求在平台生成包。新增 node 域持久构建记录 `ai_node_application_release`，
采用 MySQL 队列、条件领取与带所有者/有效期的更新条件；独立托管调度器续租，
独立有界执行器运行受信构建脚本。当前网页只提交版本/说明及幂等编号，由后端默认发布配置决定程序、依赖和适用设备，不能指定路径或命令。
复用 infra 文件存储的本地 Path 流式契约，S3 SDK 走内部 endpoint，前端按权限获得短时下载链接。
不添加微服务，不在事务内执行构建或大文件上传，不把任务状态放在单机内存作为事实源。
引导工具与应用从同一份已验签源码生成，生成动作不触发设备升级。

## 统一应用包交互修订（2026-10-06）

按用户要求，RK3566 / RK3568 / RK3588 共用程序和依赖，生成页不再逐机型选包或要求用户勾选
数据兼容性。后端解析默认配置，签名清单一次记录多个支持型号；设备自动预检并拒绝不兼容包。
这没有改变 schema 1 的向后兼容约束，发布验收仍须覆盖数据兼容性和实际系统/NPU/视频驱动。
保留旧 profile 请求字段及历史配置，已有记录的重试和下载沿用原身份；无 profile 的幂等重放即使
默认配置变更也返回原任务，不重新构建。
