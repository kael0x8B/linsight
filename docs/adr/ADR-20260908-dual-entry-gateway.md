# ADR：网关自治与平台、本地双入口

- 状态：用户于 2026-09-08 明确要求「可以用平台管理，也可以独立运行，想从哪访问就从哪访问」，并授权实施。
- 背景：当前 Agent 接受中心命令，Runtime 不保存任务启动配置，上传后的证据会清理，无法作为可独立管理的设备交付。

## 决策

网关拥有实际执行配置、独立递增的 gatewayRevision、任务期望状态和本地事件记录。Java 继续拥有租户、中心资产目录、编排意图和中心事件处置。平台与本地网页均通过网关管理服务修改同一份执行配置，无模式切换。平台命令中的 configVersion 仍表示中心配置版本，不与 gatewayRevision 混用。

本地管理入口在 Runtime 内调用现有模型池、TaskManager、规则引擎；局域网 HTTP 入口仅代理明确的网关操作，不暴露 Runtime 密钥和任意内部 API。界面沿用现有 Vue/Vben 组件，独立打包，无 CDN、中心登录或中心 API 依赖。平台通过现有节点反向通道使用相同的管理接口。

2026-09-09 用户明确要求不逐节点手动安装额外服务：本地入口并入原 Runtime 进程的生命周期，使用相同事件循环与进程内 ASGI 传输。原 Runtime 启动命令不变，自动监听 48901；无需另一个 Python 进程或 systemd 单元。升级自动停用旧单元并保留回滚状态，部署验收同时验证网页入口。内部 API 的回环监听边界不变。

配置修改采用 expectedRevision 与 requestId：同一版本最多一次修改成功，重复请求幂等，旧版本返回冲突。运行调整先验证并持久化期望配置，再应用；失败明确保留待恢复状态，后台重试。运行/停止意图都必须持久化，停止后的任务不能因重启复活。源地址等配置使用设备本地密钥加密，UI 和运行上报不包含摄像头凭据。

中心再次启动同一 configVersion 时复用网关已有配置；只有明确更新中心 configVersion 且版本校验通过才接受新配置。中心下发时固定观察到的 gatewayRevision，恢复联网不自动覆盖本地修改。中心运行上报包含网关版本与脱敏执行配置，平台单节点工作台直接读取网关。

启动校验、容量预检和启动命令也必须使用这份实际执行配置：仅复用同一任务、摄像头、算法、Pipeline 和 configVersion 的已认证网关上报；显式更新中心 configVersion 后使用新中心配置。校验期间 gatewayRevision 发生变化时拒绝提交，保留模型发布、部署就绪及算法验收门禁。容量预检按模型池实际驻留状态估算新增内存，已缓存且可用的模型不重复扣减，也不提前计入尚未驱逐模型的释放内存。

模型制品和部署元数据本地持久化，Runtime 自行恢复模型与任务，不依赖 Agent 成功注册/心跳。事件上传确认与本地历史保留分离；已有离线补传幂等协议保留。本地历史按保留期清理，尚未确认上传的证据不静默删除，积压通过现有磁盘/补传指标呈现。

## 影响与替代方案

不在网关部署完整 Java/MySQL/Redis/MinIO，不复制推理引擎，不建立可切换的两套配置。沿用 SQLite WAL 增加网关本地配置存储；这是对原「Runtime 不拥有业务配置真值」及「浏览器只访问 Java」的明确、有限例外，仅适用于单节点执行配置和受鉴权的网关入口。

中心的全局目录和跨节点处置不迁入网关。单节点实时管理与结果查询可由两个入口完成；中心离线时平台显示不可达，本地入口继续可用。

## 迁移与回滚

现有节点升级后，下次接收任务配置时自动形成本地持久快照；升级前已在内存中的任务需要重发一次配置。已有模型注册表兼容读取。已有数据库增加本地历史表，无中心数据库结构迁移。回滚源码前保留 runtime-data（包含本地密钥、配置数据库、模型和证据）；旧版本不会读取新网关配置，需由平台重新下发任务。回滚不能宣称仍具备自治能力。

## 验收

覆盖首次配置、本地与平台并发修改、重复命令、断线旧命令、Runtime 重启恢复、停止后重启、模型损坏与断流重试、本地历史在上传后仍可查看、未登录访问与越界路径拒绝、无中心服务的浏览器流程。工程测试和现场实流验收分别记录，不将 Mock 测试当作现场验收。
