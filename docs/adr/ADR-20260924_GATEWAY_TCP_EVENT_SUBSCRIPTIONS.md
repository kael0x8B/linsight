# ADR：盒子事件接口改为 TCP 服务端订阅

- 状态：2026-09-24 用户明确要求变更事件接口协议；按此决策实现。
- 背景：原盒子主动 HTTP 投递要求为每个接收方维护地址、网络策略、重试和路由。现场改为业务客户端主动连接盒子订阅；事件须清楚携带识别内容、图片、摄像头、算法、类型和扩展属性。

## 决策

复用现有 Runtime 网关进程、SQLite 事件库与本地截图，不引入新服务或消息中间件。新增独立 TCP 监听，UTF-8 NDJSON 帧、HMAC-SHA256 挑战鉴权、客户端任务及事件类型过滤、单调游标重连。事件创建和 TCP 历史写入处于同一本地事务；截图由独立媒体引用保护至历史保留期。平台事件上传与 Webhook 保持独立。

TCP 监听默认绑定 `0.0.0.0:48902`，订阅开关默认关闭。网络明文由受控内网、VPN 或 TLS 终结代理保护；不要在公网裸露。单连接最多 16 个并发，未鉴权/未订阅命令 10 秒超时，慢客户端断开。接收方处理成功后自行持久化游标并按源事件 ID 去重；盒子不维护每个客户端的消费状态。

## 备选方案与影响

继续 HTTP 推送不满足客户端订阅方向。改用 WebSocket 或消息代理增加额外协议/部署依赖，当前没有必要。平台 Webhook 不替代盒子本地事件订阅。影响 Runtime、网关本地/平台工作台、协议文档和接收方集成；Java 控制面、平台事件主记录和算法识别流程不改变。

## 迁移、兼容、回滚

升级后停止旧 HTTP worker 与旧 RPC；旧目标、路由、投递记录保留供核对，旧未完成投递不自动映射到 TCP 客户端，原旧队列媒体引用释放。接收方须更换为 TCP 客户端并记录游标。升级前备份 runtime-data，导出需要补发的 HTTP 积压事件。回滚旧版本前先停用 TCP，检查旧 HTTP 目标与积压是否仍应执行。V2 事件包含原 V1 的通用数据字段，传输语义为明确的不兼容升级，通过 `event.tcp.v2` capability 区分。

## 验收

验证鉴权失败、密钥轮换、订阅过滤、截图校验、断线续读、过期游标与平台上传独立性；现场需再完成接收端和真实摄像头联调。执行证据记录在相应测试与构建输出中。
