# 入口主动刷脸核验实施说明

支持 RK3566 NPU、参考登记、指定刷脸区自动触发、入口权限、连续帧确认和事件证据。现场准确率及阈值需单独验收；本功能不自动控制门禁。

## 模型与运行后端

RK3566 使用 `RKNN_FACE_PAIR_SFACE / RKNPU` 执行后端，YuNet 检测与 SFace 特征提取使用匹配的 RKNN 模型包。安装 ONNX 文件不会自动启用 NPU，后端执行失败不会静默回退 CPU。

InsightFace / ArcFace `buffalo_l` 512 维模型属于另一条引擎链路。当前入口功能使用 SFace 128 维，不需要下载其他引擎链路的模型，既有 512 维参考数据不能直接混用。

## 从哪里使用

当前日常入口已统一为 **摄像头 → 算法设置 → 添加识别算法 → 入口主动刷脸**。直接选择人员库、允许人员和画面刷脸区，节点/模型/阈值收进高级设置；同处提供启停、移除和状态。登记人员可就地打开，也可从识别参考库的“人员登记”进入。详见 `docs/CAMERA_ALGORITHM_MANAGEMENT.md`。

以下为保留的底层流程与诊断能力说明，日常配置不要求按四个页签操作：

1. **人员登记**：选择入口授权人脸库、推理网关和 NPU 模型版本，填写姓名、工号、授权有效期，确认本人授权并上传照片。网关检查单脸、尺寸、位置和图像质量，实际提取成功后才可用于核验；失败状态不能通过普通条目编辑伪造成有效参考。
2. **入口配置**：管理员选择摄像头、网关、参考库、NPU 模型和允许进入的人员，触发方式选择“指定刷脸区自动触发”；将识别区域限定在明确标出的刷脸站位，再保存并启用。自动区域不超过画面一半，避免把办公室整幅监控画面作为主动入口。相似度 0.6、3/5 帧只是开发初值，需现场校准。
3. **主动刷脸**：访客主动到指定站位正对摄像头，站稳约 1 秒后由网关自动发起一次核验；访客不登录平台、不勾选平台复选框、不点击开始。结果展示姓名、人员编号、实际推理设备、帧数、相似度和告警链接；核验完成后须离开，再接待下一位。站稳时间只是触发条件，不等于端到端出结果耗时。管理员页面可独立查看取景和状态，关闭页面不停止自动值守。“手动发起（开发诊断）”仍保留原来的确认和开始按钮。
4. **核验记录**：查看最近 50 次登记/核验与关联事件。事件中心可查看标框截图、录像和处置记录。

**停用**入口会取消排队/运行的会话；**删除**要求先停用，历史核验和事件保留。人员可撤回授权，过期或撤回的参考不再参与后续核验，并使相关在途会话失效。手动诊断的取消、超时或关闭弹窗会停止该次分析；自动值守不依赖弹窗，须停用入口才能停止后续自动触发。如摄像头还有其他预览消费者，共享视频解码由原所有者管理。

## 结果口径

| 结果 | 行为 |
| --- | --- |
| 同一参考身份满足 N/M 且具有入口权限 | 显示身份确认及权限通过，不生成异常事件 |
| 身份满足 N/M 但没有该入口权限 | 生成“入口权限异常”事件 |
| 有效单脸连续满足未匹配条件 | 生成“入口身份待核查”事件，供人工核查 |
| 无脸、多脸、低质量、候选身份过于相近、帧数不足 | 提示重试，不据此产生权限异常 |
| 配置改变、授权撤回、会话取消或超时 | 取消/结束本次结果，不继续授权 |

“身份待核查”不表示已经非法进入；实际越界需通行传感器或门禁记录。所有结果明确 `liveness=NOT_VERIFIED`，本功能没有抗照片、屏幕或录像攻击的活体能力。合成照片视频能通过同图匹配，是软件测试数据，不是活体通过证明。

## 所有权与执行契约

- **algorithm**：`ai_face_reference` 扩展既有库和条目，管理授权、模型版本、MinIO 原图 SHA256、节点验证状态；只提供有效参考投影。
- **model**：`FACE_VERIFICATION / FACE_PAIR_SFACE_RKNN` 固定契约；ARCHIVE 仅该专用解码器允许 RKNPU，通用模型包仍按原规则约束。
- **task**：`ai_entry_access` 版本化入口配置；`ai_entry_scan` 有限会话、权限快照、结果和事件关联。保持普通持续识别任务原有语义。
- **node / Agent**：`ENTRY_FACE` 耐久命令，节点鉴权、下载校验、轮询取消、回执重放、证据补传。
- **Runtime**：既有 ModelPool、共享摄像头解码，单脸质量检查、对齐、NPU 特征提取、1:N 比对、多帧确认。Java 不做逐帧推理。
- **event**：复用事件、处置、通知及证据服务。同一次会话在数据库事务中幂等创建事件，不伪造普通 task/rule ID；入口事件相关外键可空。

管理接口：`/admin-api/ai-video/task/entry-access/{list,save,stop,delete,enroll,start,cancel,get,history,station-status}`；参考状态及撤回：`/admin-api/ai-video/algorithm/face-reference/{list,revoke}`。节点接口为 `/node-api/ai-video/task/entry-access/{command,state,stations,auto-start,station-report}`。复用任务、参考库和模型测试权限，在服务端检查租户、节点、一次性命令及当前配置；浏览器不提交可信相似度或权限判断。

## 自动刷脸运行机制

- Runtime `rule/face_zone.py` 管理 `WAIT_CLEAR → READY → POSITIONING → TRIGGERED → SCANNING → WAIT_CLEAR`。启用、重启或失去权威配置后先要求区域清空约 1 秒；正对镜头的完整单脸稳定约 1 秒才触发。同一人持续停留不重复触发；多人或姿态不满足条件不会启动身份会话。
- `task/entry_station.py` 复用摄像头共享解码和模型池，只在指定站位做 NPU 人脸定位；正式特征提取仍在有限 `ENTRY_FACE` 会话内。当前每节点最多 2 个自动入口，同一摄像头不重复值守。
- Agent 每秒同步入口配置与状态，遇到触发后请求 Java 创建耐久命令。Java 验证租户、节点归属、入口版本、观察时间、有效参考、当前在途会话；相同 encounter UUID 幂等返回原会话。自动命令具有系统审计身份，不要求浏览器管理员登录。
- Runtime 配置租约 15 秒，Agent 同步失败即主动撤销值守；进程断开时租约自动到期。页面关闭不影响值守，但中央平台服务仍需可达；本功能不提供脱离平台的离线身份授权。恢复后先清空区域，不能对持续站着的人自动重放旧会话。
- 自动值守心跳为可重建临时状态；业务配置、核验与命令继续由 Java task/node 域持久化。没有新增微服务、数据库或框架。

## 资源与证据

- 单库最多 256 个有效/待验证参考；每张 JPG/PNG ≤5 MB，一次参考下载合计 ≤100 MB。
- Runtime 最多 2 个并行会话，同一摄像头仅一个入口核验；总截止 120 秒、现场采集最长 30 秒，最多 90 帧。
- 参考特征在 Runtime 内存中按模型版本和图片 SHA 缓存，容量 256；不向浏览器返回特征向量。Agent 参考临时下载在完成后清理。
- 每次登记使用独立 UUID 文件名，避免后续登记覆盖先前照片。对象存储的匿名读取已验证返回 403；节点使用短期签名链接。
- 截图和本次主动采集录像上传 MinIO。盒子只做有限缓存和耐久补传：单会话采样预算约 24 MB，入口证据积压上限 200 MB，达到上限拒绝新会话。上传收到确认后删除本地证据；断网保留重试。
- 录像覆盖主动会话采集阶段，不采集会话开始前的人员视频，不能称为“告警前10秒后20秒”录像。

## 停止与预览

停止命令固定观察到的网关配置版本，页面区分待确认状态与失败原因。实时预览可查看入口刷脸区、实际人脸位置、当前提示和最近结果；缺少有效参考时明确提示登记。

## 使用边界

真人准确率、光照角度、现场阈值和抗攻击能力需要独立验收；合成人像、Mock 和单元测试不能替代。登记与通行权限分别管理，参考提取成功不自动授予通行权限。

平台配置入口和网关归属见 [网关双入口说明](GATEWAY_DUAL_ENTRY.md)，已有人员照片处理见 [特征提取说明](FACE_REFERENCE_EXTRACTION.md)。
