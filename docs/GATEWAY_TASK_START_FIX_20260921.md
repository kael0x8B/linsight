# 17 网关平台启动失败修复（2026-09-21）

用户从平台网关详情启动“厂区车辆识别 · 17盒子验证”（任务 33）时提示“任务配置不符合已发布 Pipeline 或模型门禁”。验证节点固定为 `192.168.2.17` / `rk3566-field-001` / 节点 1。

## 原因与修改

1. 网关执行配置已使用车牌 NPU 模型版本 138、OCR 137、车辆检测 121，并设置采样 4 FPS；中心原始编排意图仍绑定车牌版本 136、采样 1 FPS。版本 136 已被新发布版本替代。Runtime 按自治约定在同一 configVersion 下复用本地配置，但中心启动校验仍读取旧意图，错误拦截了可运行的配置。
2. 首次修复后实测平台启停，又复现内存预检错误：已停止任务仍缓存 3 个模型，系统可用内存已扣除这些模型，旧计算再次扣除 192 MiB，误报低于 512 MiB 安全余量。

`TaskServiceImpl` 统一按同版本网关执行快照进行启动校验、模型容量检查及启动命令组装。校验任务归属及配置版本，并固定校验时的 gatewayRevision；发布状态、模型能力、部署就绪、Pipeline 验收、参数及并发门禁保留。显式修改中心配置版本仍使用新中心配置，不回写或覆盖本地 ROI、规则、模型和参数。

`ModelPool.capacity_preflight` 按实际存活的驻留模型估算增量内存，避免对可复用模型重复计费；不把尚未驱逐的缓存算作已释放。仍保留 512 MiB / 节点安全比例及模型槽位限制。本次修改适用于通用识别任务。
