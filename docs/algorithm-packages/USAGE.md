# 算法配置与算法包使用

## 从算法到识别

1. 在 **算法中心** 找到算法，点击 **配置识别**。同名算法合并为一张卡片，已发布算法包优先；原有编排与历史验证记录保留在详情。
2. 选择执行网关和摄像头。从 **网关 → 识别算法 → 添加识别算法** 进入时已固定网关；只有一台可用摄像头时自动带入。选择“安全帽检测”等算法即可自动匹配依赖，不必先去模型中心安装，也不必逐项选择模型版本。
   **车牌识别**、**厂区车辆识别**属于内置编排，也在同一个算法下拉框中；选中后进入内置编排配置，保留刚选的网关和摄像头。RK3566 网关会显示已发布的车牌检测与 OCR 模型版本，缺少的模型在提交时准备；低清车牌的 10% 重裁剪能力需要安装对应的新版 Runtime。
3. 默认使用算法声明的识别参数；**高级设置** 保留模型版本、配置名称、分析帧率、置信度及专用参数。人员库、指定人员等没有默认值的必要配置仍需填写；不能替用户选择身份或现场区域。
4. 在 **告警条件** 中调整参与告警的目标、持续时间、连续帧和告警间隔。算法包可自带默认规则，也可从已发布模板复制；每个识别配置独立保存，不会覆盖另一网关。
5. 需要区域时点击 **获取摄像头画面 → 截取当前画面 → 重新绘制 → 保存区域**。画面沿用实时预览组件，区域以归一化坐标保存。没有截图时显示获取入口。
6. 点击 **部署并启动**。系统复用已经就绪的模型，自动下发缺少的模型和算法包；全部就绪后再启动。安装失败会显示原因，未就绪时不启动任务。到 **边缘网关 → 目标网关 → 识别算法** 查看实际运行状态和画面。

启停集中在所属网关。停止保留配置；删除需要先停止。平台和网关本地使用同一份执行配置。旧编排保留原有兼容配置流程，已有任务不自动迁移为算法包。

### 自动匹配的前提

平台需事先具备已发布、通过执行测试的模型和算法包。资源准备由算法维护人员完成一次，现场配置人员不重复制作模型或算法。缺少资源时界面说明原因，不展示虚假的“可部署”。

模型同时满足算法角色的任务类型、标准标签和格式要求，以及网关运行环境要求。先复用当前网关已安装的兼容版本，再优先匹配已声明执行后端和目标的专用版本、模型目录默认版本，最后按版本 ID 确定顺序。发布新模型不会替换已有任务的固定绑定。

新 Runtime 在心跳中上报 `modelEnvironment.providers`，明确列出可用执行后端、设备类型、制品格式、目标和运行库版本；不会因 Torch 尚未安装在 Runtime 主环境中，就误判隔离 CPU 环境不可用。模型运行契约用 `execution.provider / target / runtime / minRuntimeVersion` 声明要求；RKNN 历史清单仍可用 `targetPlatform`（如 `rk3566`）。同一训练权重可以分别转换为 RK3566、RK3588 或其他设备的不可变制品，由平台在所选网关上自动选择匹配版本。当前目录把不同目标制品登记为独立模型资产，它们可以引用同一源 ONNX 与 revision，发布新目标不会替代另一个目标的可部署资产。

RK3566、RK3588 和后续新增盒子可以同时纳管。平台不固定规定某个算法只能运行在哪一种盒子上；只要算法依赖存在与节点能力匹配的已发布制品，并通过容量预检，就可以部署。没有目标声明的历史加速模型只复用本机已经就绪的版本，不能凭名称推断另一台盒子的兼容性；新盒子也可以回退使用匹配的通用 ONNX 版本。

匹配表示部署前提成立，不代替模型下载校验、实际加载、容量校验或现场准确率验收。旧网关继续支持已安装模型和原有 ONNX 路径；新的硬件匹配需要升级 Runtime/Agent 及控制面。网关本地离线入口仍使用已安装资源，自动从平台准备资源由上述平台入口完成。

## 状态分别代表什么

- **可配置 / 可试运行**：当前版本允许进入配置流程；能否启动还取决于网关能力、模型就绪和配置校验。
- **运行中**：来自网关任务状态，表示当前正在执行。
- **现场验证记录**：在算法详情查看。历史编排没有验证记录时显示“尚无现场验证记录”，不再把缺省 PASS 展示为“已通过验收”。

安全帽、反光衣的现场验证记录仍是 PENDING。连续运行只能说明程序能够持续执行；现场准确率需要实际场景的正反样本、误报漏报与性能记录。没有这些证据时不自动改为通过。

## 算法包上传和下载

入口是 **算法中心 → 上传 / 下载算法包**。

- 上传 ZIP：根目录放 `algorithm.json`（标识、版本、模型依赖、参数和可选默认告警规则）、`processor.py`（SDK 算法实现）；可以附带 `README.md`。
- 模型权重在 **模型中心** 单独管理，配置时绑定并下发到网关。ZIP 最大 8 MB。
- 上传后查看版本校验结果并发布。同一 code/version 的不同内容不能覆盖，修改后必须升级版本号。
- 点击 **下载 ZIP** 获取该不可变版本的原始包；**包内容与制作说明** 提供结构说明与已发布示例的下载入口。

仓库已提供安全帽、反光衣、区域入侵、人员库刷脸、跌倒和车辆违停包。开发者运行 `python3 scripts/build-algorithm-packages.py`，输出在 `artifacts/algorithm-packages/`。SDK 契约见 [开发说明](README.md)。

## 已有配置升级版本

在平台 **边缘网关 → 目标网关 → 识别算法**，先停止对应配置，再点 **更多 → 配置参数**。在 **选择识别 → 识别算法** 选择同一算法的已发布版本。兼容的原模型绑定、同名参数、摄像头和原告警条件会保留；原绑定不再兼容时需在 **高级设置** 重新选择。核对后点击 **部署并启动**。发布新包不会自动替换其他任务。

## 安全帽头部框与告警区域

画面上的检测框现在称为 **识别标注**。告警 ROI 是判断目标是否位于指定区域的范围，二者分别控制。

安全帽包 **1.0.2** 默认显示模型提供的安全帽或未戴帽头部证据框；反光衣包 **1.0.2** 默认显示对应穿戴证据框。需要人员全身框时，在所属网关的 **更多 → 配置参数 → 识别参数** 打开 **显示人员全身框**。关闭即可恢复证据框。该字段来自算法包 Schema，平台与网关本地编辑器共用，不需要修改平台代码。

标注上的百分比来自对应穿戴证据，不再使用人员检测置信度。没有足够穿戴证据时保持 **待确认**，默认隐藏；需要排查时打开画面旁的 **显示合规与待确认目标**。待确认显示人员位置且不附带穿戴判断分数，不按全身比例虚构头部框。这个显示设置不会改变人员跟踪框或告警区域判定。

旧编排保留原有兼容行为；已删除的旧配置不会恢复。算法包升级不等于更换模型，也不等于现场准确率已通过验收。

## 新增算法默认条件

| 算法 | 模型要求 | 默认告警条件 |
| --- | --- | --- |
| 跌倒检测 | 具有 `fall` 类别的检测模型 | 置信度 0.6，5 帧中 3 帧命中，持续 2 秒 |
| 车辆违停检测 | 具有 `car / truck / bus` 类别的检测模型 | 置信度 0.5，5 帧中 3 帧命中，连续静止 120 秒，位置容差 0.02 |

跌倒不会把普通人员框直接当作跌倒。违停相对于停车起始位置累计判断位移，移动或检测中断会重置持续确认。使用前应在实际摄像头上绘制禁停区域并确认时长、跟踪稳定性和效果。

## 规则中心的用途

规则中心用于告警模板和不可变版本管理、离线试算及复用。日常操作在网关配置内完成：模型置信度等属于 **识别参数**；区域、持续时间、连续帧和间隔属于 **告警条件**。普通配置不需要先单独创建规则。

## 缺少配置选项时

- 没有在线网关：检查网关连接和执行状态。
- 没有兼容模型：在模型中心完成格式验证、单图测试和发布，选择目标设备支持的模型；不得通过修改 READY 状态绕过检查。
- 旧编排缺少告警规则：在规则中心发布匹配事件类型的模板，再重新打开配置。
- 版本未发布或缺少资产：在算法详情、算法包管理中补齐。算法包需要支持 SDK 1.0 的网关，可通过在线升级更新。
