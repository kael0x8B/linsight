# 摄像头算法管理

更新：2026-10-12。

## 当前入口

按用户要求，摄像头列表和卡片已移除“算法设置”“批量配置算法”及能力标签的配置跳转；2026-10-12 进一步移除列表的识别能力列和卡片的能力数量。算法配置与启停保留在边缘盒子。实时预览直接点击能力卡片查看结果，使用“识别 ROI”开关显隐检测框和刷脸区域；不再提供“AI 识别 / 实时视频”模式切换。底层配置、任务 API 和已有数据保留。

下文为 2026-09-07～08 的历史实现与验证记录，其中摄像头配置入口已由上述交互替代。

## 给一台或多台摄像头添加算法

1. 打开“摄像头管理”。单台点击“算法设置 → 添加识别算法”；多台先勾选摄像头，再点“批量配置算法”。列表和卡片都支持选择，跨页保留，每批最多 100 台。
2. 选择安全帽、反光衣等识别算法。已有可复用配置时，选择一套配置，页面展示执行节点、分析频率、告警规则、检测区域和运行模式。
3. 没有现成配置，或需要不同节点、模型、告警区域时，点击“新建一套算法配置”。向导会带入所选摄像头和算法，只需完成一次配置，任务名称和编码自动生成。
4. 点击“保存配置”，逐台查看“已保存”“已有配置 · 未修改”或失败原因。保存不会启动识别，已有相同算法的摄像头不会重复添加、覆盖或自动启动。
5. 对本次新增配置，可明确点击“启动本次新增配置”。也可以稍后在每台摄像头的“算法设置”中单独启动。

同一摄像头可添加不同算法，例如安全帽检测与反光衣检测。每种算法使用独立任务，可分别停止或移除。

批量复用保留原模型版本、执行节点、参数及告警规则。非全画面的检测区域需要确认适用于目标视角；全画面不额外要求确认。摄像头视角不同且需要不同区域时，应为相应摄像头选择合适的规则。

本批摄像头会使用所选配置的执行节点。批量配置不代表节点可以同时承载任意数量视频，应按实际容量分批启动。

## 停止和移除的区别

| 操作 | 对这台摄像头的影响 | 保留内容 |
| --- | --- | --- |
| 停止识别 | 下发停止命令，等待节点确认 | 算法配置、历史告警，可再次启动 |
| 移除算法 | 删除该摄像头对应的任务配置，只允许草稿或已确认停止的任务 | 算法库资产、其他摄像头任务、历史告警 |

停止中、节点离线或状态过期不等于已确认停止。此时可以下发或重试停止命令；命令排队等待节点恢复连接，确认停止后才开放移除。没有强制删除运行任务或删除全局算法的快捷操作。

需要替换已有算法配置时，先停止并等待确认，再移除此摄像头上的配置，随后添加新配置。

## 权限与实现边界

- 配置仍由任务域维护，摄像头页面作为入口；未引入第二套算法绑定关系。
- 创建、启动、停止、移除分别复用 `ai-video:task:create/start/stop/delete` 权限和租户隔离。
- `POST /ai-video/task/batch-create` 逐台提交草稿，一台失败不回滚其他摄像头。请求标识及任务唯一编码保证同次请求重试不会重复创建；删除后的旧请求也不会恢复任务。
- 保存草稿检查摄像头启用、发布的 Pipeline、模型资产、规则和有效节点。节点在线及模型部署就绪在启动时检查，保存草稿不会发送启动命令。

## 主动刷脸使用同一摄像头入口（2026-09-08）

在摄像头的“算法设置 → 添加识别算法”中选择“入口主动刷脸”。当前摄像头自动带入，选择参考库与允许通行人员，在取景截图上拖动框选现场刷脸站位，点击“保存并启用”。节点、NPU 模型和常用阈值自动预选，可在高级设置中调整；保存仍由服务端校验模型部署、有效参考、区域、版本与节点容量。

已有摄像头绑定会显示在相同能力卡片中，可直接配置、启动、停止和移除；状态包含实际值守心跳，不能把保存或启用意图当作已在识别。参考人员登记一次后可复用到多个摄像头，不再要求另行创建入口名称、重复选摄像头或每次点击开始。

人员库页面管理照片与授权；摄像头算法配置管理通行范围。照片登记可从摄像头配置内打开。允许人员留空表示无人取得权限；选择“允许库内全部有效人员”会选择当前有效人员，新登记人员不会在不保存配置的情况下自动获得权限。多人场景须逐人进入明确标出的主动刷脸区，现有 NPU 自动会话和告警/MinIO 逻辑不变。

内部继续复用 task 域的入口配置与有限会话，不新增摄像头关系表或普通持续任务的伪 ID。CameraOverview 批量组合只读投影；入口能力使用 entryAccessId，普通任务保留 taskId。多个摄像头分别确认 ROI，当前每节点最多两个自动刷脸站位。

验证证据见 `artifacts/camera-face-configuration-20260908/`。
