# 已录入人员的特征提取

进入“识别参考库 → 入口授权人脸库”，在已有人员卡片点击“提取特征”。照片、姓名、编号和人员库沿用原档案，不创建第二个人员。选择在线网关及已部署的核验模型（现场为 #131 RK3566 NPU），填写参考有效期并确认本人登记授权，点击“开始提取”。

卡片显示待提取、提取中、已就绪、提取失败或提取超时；处理中的卡片每 3 秒更新。失败会给出单人照片、脸部大小、清晰度或节点执行等提示，可更换照片后重试。关闭弹窗不会取消后台提取。超过 3 分钟仍无结果可重试；旧命令结果不会恢复已替换的参考。

实际校验通过后，原 entryId 对应的参考进入摄像头可选人员列表。参考库和模型须匹配，人员须启用且参考未过期。管理员仍需在摄像头“算法设置 → 入口主动刷脸”中选择允许通行人员并保存；提取成功不授予通行权限。

FACE 特征状态由网关回执维护，不能手工设置 READY。更换照片撤销旧参考并恢复待提取；修改部门和说明保留服务端提取结果。

## 实现

- Algorithm 领域 FaceReferenceService 维护参考和人员状态；Infra 根据已登记的存储路径读取照片，不接受外部 HTTP 下载目标，不新增照片读取 HTTP 接口。
- Task 领域 POST /admin-api/ai-video/task/entry-access/extract 接收 entryId、nodeId、modelVersionId、consentConfirmed、validUntil。有效期使用平台毫秒时间戳约定，前端转换日期控件值。
- 权限：ai-video:library:update 与 ai-video:model:test；同权限的 /extraction-status?id=... 仅返回 ENROLL 会话。
- 图片读取在事务外；原人员锁定、参考创建、ENROLL 会话与 ENTRY_FACE 持久命令在同一事务。并发请求拦截，重试撤销旧参考。记录保存在已有 attributes.faceExtraction 中，不暴露向量、下载链接或底层异常文本。
- 继续使用 RKNN_FACE_PAIR_SFACE 运行后端和节点 ENROLL 协议；无新增后端或数据库迁移。只覆盖本次相关 Java 类，Runtime/Agent 未变更。
