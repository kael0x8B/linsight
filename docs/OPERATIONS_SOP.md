# LInsight Operations SOP

## 使用原则

先确认告警对象、开始时间、影响摄像头/任务/节点和对应 `traceId/runId`，再处理。不要通过删除离线队列、事件库或证据文件来“消除”告警。涉及重启、降路数、切版本或删除文件时，先保全日志、Runtime snapshot 和相关事件编号。

## 告警处置

| 告警 | 首先检查 | 判断标准 | 处理动作 | 恢复验证 |
| --- | --- | --- | --- | --- |
| 摄像头离线 > 5 分钟 | 摄像头供电、交换机、RTSP 探测、鉴权、节点到摄像头路由 | 单摄像头异常通常为设备/链路；同节点大量异常优先查网络或 Runtime | 恢复供电/网络/凭据，执行连接检测；不要盲目重启全部任务 | 在线状态恢复，输入 FPS > 0，重连计数停止增长，预览成功 |
| 磁盘 > 80% | 事件证据目录、日志、离线 backlog、MinIO/中心连通性 | 离线队列和证据持续增长说明补传阻塞；普通日志增长说明保留策略异常 | 先恢复补传，再按保留策略清理已确认上传的数据；禁止删除未确认事件 | < 80%，`missingMediaFiles=0`，队列开始下降 |
| 磁盘 > 90% | 同上，并确认剩余空间和写入失败 | 已接近事件/SQLite 写入失败 | 暂停新增非关键任务或降低证据时长；保留未上传证据，立即恢复中心链路 | 写入测试成功、SQLite 完整、队列无丢失 |
| CPU > 90% | 系统、AI、Java 三者 CPU，任务路数，解码 FPS，异常循环 | AI 高通常为路数/模型超容量；Java 高查 API/补传；系统高查其他进程 | 按容量报告降到推荐路数；修复异常任务或限流；保留现场指标 | CPU 连续 10 分钟低于阈值，FPS/时延恢复 |
| 内存 > 90% | 系统内存、AI RSS、JVM Heap/GC、模型池、OOM 日志 | AI RSS 高查模型实例；JVM Heap 高且 GC 无法回收查泄漏/积压 | 停止新增任务，按节点模型池卸载策略处理；必要时受控重启单服务 | 内存稳定、无 OOM、任务与补传恢复 |
| GPU/NPU/显存 > 90% | 设备利用率、显存、温度、功耗、模型实例和批大小 | 显存持续高且加载失败为容量问题；温度高同时降频为散热问题 | 降路数/批量/输入尺寸到已验收配置，检查散热；禁止临时关闭 OOM 保护 | 无加载失败，温度稳定，P95 恢复 |
| AI FPS 明显下降 | 输入 FPS、解码 FPS、推理 FPS、CPU/GPU、温度、队列 | 输入正常但推理下降查模型/算力；输入也下降查 RTSP/解码 | 隔离异常摄像头/模型，回到容量报告推荐路数，必要时回滚版本 | FPS 回到一小时基线 70% 以上且队列不增长 |
| AI P95 异常 | preprocess/inference/postprocess/total 四段时延 | 只 inference 高查后端；preprocess 高查解码/缩放；postprocess 高查目标数量/规则 | 根据阶段定位，降低已验收范围内的负载，保留慢请求样本 | P95 < 2 秒并持续 10 分钟 |
| 模型加载失败 | 模型 SHA256、格式、Adapter、设备后端、内存 | hash/格式错误禁止重试；资源不足可重试但需先释放资源 | 重新下发匹配版本；不得用测试/空权重替换；必要时回滚模型版本 | 模型 READY、单图测试通过、任务恢复 |
| Offline Queue 持续增长 | 中心可达性、DNS/TCP/HTTP 状态、429 Retry-After、磁盘 | 网络恢复后仍增长说明补传或幂等失败 | 恢复网络/中心服务；检查退避、死信和服务端幂等键，禁止清库 | Queue 归零、重复数 0、历史顺序与媒体完整 |
| 事件长时间未补传 | Oldest Event Age、重试次数、死信、媒体文件 | 年龄 > 15 分钟或重试已达上限为严重 | 按 sourceEventId 检查事件/媒体，修复单条错误或服务端契约；保留原始文件 | 该事件和媒体中心可见且本地仅在 ACK 后删除 |
| 服务频繁重启 | systemd/Docker restart 次数、退出码、OOM、健康检查、版本 | 同一服务 15 分钟 > 2 次为异常 | 停止自动重启风暴，保留 core/log；若由新版本导致，执行回滚演练流程 | 版本与清单一致，稳定 30 分钟，任务/摄像头/补传正常 |
| HTTP 错误率/时延异常 | `/actuator/prometheus`、数据库连接池、外部存储、Webhook | 5xx 为服务错误；429 为限流；P95 > 500ms 先排除大文件接口 | 查 traceId 和慢 SQL，隔离异常外部依赖，按需限流 | 95% 管理 API < 500ms，错误率回落 |

## 每次处置必须留存

记录告警名称、开始/恢复时间、节点/摄像头/任务、版本清单、原始指标、日志/traceId、采取的动作、数据完整性验证和责任人。发生离线补传、模型加载失败、升级回滚或磁盘 > 90% 时必须附 Runtime snapshot；涉及版本时必须附 `release-manifest.json`。

## 禁止动作

- 不得删除 `delivery.sqlite3`、未 ACK 的事件/媒体或死信来恢复指标。
- 不得把 `WAITING_FOR_*`、`PENDING` 或 Mock 结果改成 PASS。
- 不得以重启全部服务替代根因定位；重启前必须留存证据。
- 不得在命令、报告或截图中保存 RTSP 密码、节点密钥、访问令牌或签名 URL。
