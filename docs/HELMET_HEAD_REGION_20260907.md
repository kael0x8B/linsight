# 安全帽头部框与码流核对（2026-09-07）

## 当前识别输入

任务 2 使用摄像头 2 的 **640×480 子码流**。控制面 `TaskServiceImpl` 下发任务时调用 `getRuntimeStreamUrl(cameraId, "SUB")`。浏览器实时视频也使用子码流，识别任务和预览会话的作用不同。

当前人员模型 18 的固定输入为 640×640，安全帽模型 120 为 320×320；两者分别对整帧推理，再进行人员与 PPE 关联。主码流对应 3840×2160，但整张主码流送入当前安全帽模型仍会被缩到 320×320，不等于以 4K 分辨率逐像素识别。

## 头部框修正

安全帽模型已经输出 `helmet / no_helmet` 头部区域。原后处理关联到人员后，只保留其类别和置信度，展示沿用人体 bbox，因此框住身体。

本次在既有 attributes 中保留真实 PPE 检测区域 `ppeBoxX / ppeBoxY / ppeBoxWidth / ppeBoxHeight`，P06 对明确安全帽结论绘制这些坐标。原有人员 bbox 继续用于跟踪、ROI 和事件规则；没有按固定身体比例虚构头部位置。未知结果仍不告警，旧节点或无效头部坐标兼容原有人体框。

修改通过 Runtime 157 项测试、Ruff、前端类型检查和 ESLint；展示与坐标测试 5 项通过。测试覆盖头部位置变化时人员 trackId 与 ROI 框不变、未确认不生成头部坐标，以及前端坐标合法性和旧节点兼容。

平台源码部署 **26** 已完成，节点版本 **source-91220fb6545a**，任务 2 已恢复 `RUNNING`，新 Run 为 `87ac6cac-f9f4-4b44-bcff-0cc1a2f35d55`。节点 PPE 后处理文件 SHA256 与本地一致。升级后采集的 8 个唯一实际分析帧均带有至少一个真实未戴帽头部区域；浏览器已实际看到框围绕头部绘制，不再沿用该人员的身体框。此处验证的是坐标与展示闭环，不是“三个人已持续全部检出”。
