# 烟火漏检排查与 NPU 切换（2026-09-08）

## 排查结论

用户反馈烧纸未识别。检查时，原任务 7 持续运行、已分析约 2.7 万帧、没有确认告警，执行后端为 CPU。原配置只保留 smoke，排除了 flame；每秒 0.5 帧，规则要求 2/3 帧及进入稳定状态后持续 4 秒。这些条件会忽略仅有火焰的结果，并可能错过短暂的小目标。

没有取得烧纸当时的完整录像，当前采集的最新画面已经没有烟火，因此不能确认这次具体属于模型未检出、类别过滤还是时序条件未满足。公开烟火样例通过，不代表室内小纸火与淡烟的召回率已经验收。NPU 改善推理吞吐，不能独自解决目标太小、对比度不足或模型适用性问题。

## 现场切换配置

保留任务 ID 7 和原稳定编码，名称改为「现场烟雾与火焰报警」：

- 摄像头 2、节点 1（RK3566，192.168.2.17）。
- 算法 72327（火焰与烟雾联合检测），Pipeline 82627。
- 模型版本 128，`yolov8n-dfire-rk3566-fp16-20260908`，实际后端 RKNPU。
- 仅包含真实支持的 smoke、flame 两类；联合算法默认参数同步移除不存在的 dense_smoke。
- 模型输入 640×640，置信度 0.5，NMS 0.5；采样目标 4 FPS。
- 规则 73005 / 73107：烟雾或火焰均可触发；最近 5 帧至少 3 帧匹配，稳定后持续 1 秒；按摄像头场景聚合，恢复 5 秒，沿用 60 秒去重/冷却配置。
- 保持现场验证标记及 PENDING 验收状态，没有伪造正式准确率、误报率或实时性能门禁结果。

## NPU 转换与选择依据

沿用已批准的 RKNN 后端、固定 RKNN Toolkit 2.3.2 转换镜像和节点 Toolkit Lite2 2.3.2，不更换驱动、操作系统或推理框架。

由已验证的 ONNX 版本 127 转换：

- ONNX SHA-256：`3f6ece0156263e5b9a3c66f6717eb082c6c0f44267df158955f976372bd3c5a7`。
- FP16 RKNN SHA-256：`ba78a0e101b5c8133ad1ed729da8a05429425f20308045555b10ba51fa54bf40`。
- 输入采用 UINT8 / NHWC，RGB 归一化融入 RKNN 文件；输出沿用现有 AUTO_DETECTION 契约，标签顺序 smoke、flame。
- 8 张参考图片实机比较：FP16 与原 ONNX 检出目标数和类别一致，匹配框 IoU > 0.95、置信度差 < 0.03；NPU 单图推理 160–192 ms，原 CPU 现场约 1.3 s。
- INT8 候选版本 129 虽然约 55–78 ms，但在六张阳性参考图片上均没有检出目标，未通过等价检查，**拒绝选用**。平台默认发布版本恢复为 128。不得将 129 的“能执行”状态解释为识别效果通过。

参考图片包含 D-Fire 作者标注样例图的六个裁剪，以及两张办公室参考图。其中两张包含明显烟雾和火焰。它们只用于转换等价检查，不是独立准确率评测集；更不能代表小纸火实测。
